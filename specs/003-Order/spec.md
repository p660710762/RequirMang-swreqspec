# Feature: สั่งเครื่องดื่มออนไลน์ (Online Beverage Ordering)
Spec ID: SPEC-ORDER-001 | Source: SRS v0.1 ข้อ 3.3 (FR-ORDER) | Use case: UC-03  
Owner: <660710762> | Status: Draft v2 | Updated: 2569-09-18  
Depends on: SPEC-MENU-001 | Reviewed by: -

## Goal
นักศึกษา / ลูกค้า สามารถเลือกเครื่องดื่มที่ต้องการจากรายการเมนู  
กำหนดจำนวนและตัวเลือกของเครื่องดื่ม ตรวจสอบรายการและยอดรวม  
จากนั้นยืนยันคำสั่งซื้อและชำระเงินออนไลน์ เพื่อให้ระบบสร้าง Order  
พร้อมหมายเลข Order สำหรับใช้ติดตามคำสั่งซื้อต่อไป

## Scope
### In scope
- เลือกเครื่องดื่มจากรายการเมนู
- เลือกจำนวนเครื่องดื่ม
- เลือกตัวเลือกของเครื่องดื่มที่ระบบกำหนด
- แสดงรายการสินค้าที่เลือก
- แสดงจำนวนและยอดรวมของ Order
- แก้ไขจำนวนหรือรายการก่อนยืนยันคำสั่งซื้อ
- ยืนยันคำสั่งซื้อ
- ชำระเงินออนไลน์
- สร้างหมายเลข Order หลังชำระเงินสำเร็จ
- แสดงรายละเอียด Order หลังสร้างสำเร็จ

### Out of scope
- การจัดการข้อมูลเมนู ราคา โปรโมชั่น และสถานะสินค้า
- การจัดการผู้ใช้งาน
- การจัดการ Order ของพนักงาน
- การแก้ไข Order หลังจากยืนยันคำสั่งซื้อแล้ว
- การยกเลิก Order
- การตรวจสอบสถานะ Order
- การแจ้งเตือนเมื่อเครื่องดื่มพร้อมรับ
- การดูรายงานยอดขายและสถิติ

## Constraints
- ผู้ใช้ต้องเลือกเครื่องดื่มที่มีสถานะเปิดขายก่อนจึงสามารถสั่งซื้อได้
- จำนวนสินค้าที่สั่งต้องเป็นจำนวนเต็มที่มากกว่า 0
- ระบบต้องตรวจสอบข้อมูล Order ก่อนสร้างคำสั่งซื้อ
- การสร้าง Order จะถือว่าสำเร็จเมื่อการชำระเงินสำเร็จ
- หากการชำระเงินไม่สำเร็จ ระบบต้องไม่สร้าง Order ที่สมบูรณ์
- หากสินค้าหมดอัตโนมัติ ระบบต้องแสดงข้อความแจ้งว่าสินค้าหมดและให้ผู้ใช้เปลี่ยนเมนู
- ระบบรองรับการชำระเงินออนไลน์ด้วยคิวอาร์โค้ดแบบมีเวลาจำกัด 5 นาที
- หากผู้ใช้ชำระไม่ทันเวลาที่กำหนด Order จะไม่ถูกดำเนินการต่อ

## Requirements
- FR-06  
  ผู้ใช้สามารถเลือกเครื่องดื่มจากรายการเมนูเพื่อเพิ่มเข้าสู่รายการสั่งซื้อได้

- FR-07  
  ผู้ใช้สามารถกำหนดจำนวนและตัวเลือกของเครื่องดื่มก่อนเพิ่มเข้าสู่ Order ได้
  ตัวเลือกมีดังนี้: toppings, ระดับความหวาน, และน้ำแข็ง
  รายละเอียดตัวเลือกดังนี้
  - toppings มีให้เลือกดังนี้: ไข่มุก, ดับเบิ้ลไข่มุก, เจลลี่ผลไม้, ดับเบิ้ลเจลลี่ผลไม้, บุกขาว, ดับเบิ้ลบุกขาว, คริสตัลใส, ดับเบิ้ลคริสตัลใส, คริสตัลบราวชูการ์, ชีส, ดับเบิ้ลชีส, ซอสบราวน์ชูการ์, ชีสครันช์, ครันช์
  - ระดับความหวานต้องเลือกทุกครั้ง โดยมีตัวเลือก: หวานปกติ 75%, หวานน้อย 50%, เพิ่มหวาน 100%, ไม่หวาน
  - น้ำแข็งมีตัวเลือก: น้ำแข็งน้อย (ปริมาณน้ำเท่าเดิม), ไม่ใส่น้ำแข็ง, แยกน้ำแข็ง
  - ลูกค้าต้องเลือกระดับความหวานทุกครั้ง
  - toppings และน้ำแข็งไม่จำเป็นต้องเลือก แต่ถ้าไม่เลือกรายการใดสำหรับน้ำแข็ง ระบบจะถือว่าใส่น้ำแข็งปริมาณปกติไปเลย

- FR-08  
  ระบบต้องแสดงรายการเครื่องดื่ม จำนวน ราคา และยอดรวมของ Order ก่อนยืนยันคำสั่งซื้อ
  โดยแสดงราคาโปรชั่นที่ลดอยู่ในระบบ

- FR-09  
  ผู้ใช้สามารถแก้ไขจำนวนหรือลบรายการเครื่องดื่มออกจาก Order ก่อนยืนยันคำสั่งซื้อได้  
  และระบบต้องคำนวณยอดรวมใหม่
  หากจำนวนตั้งค่าเป็น 0 ระบบจะจัดการเป็นการลบรายการออกจาก Order

- FR-10  
  ผู้ใช้สามารถยืนยันคำสั่งซื้อเมื่อข้อมูล Order ครบถ้วน
  โดยต้องมีรายการอย่างน้อย 1 รายการ และเลือกข้อมูลที่จำเป็นคือระดับความหวาน

- FR-11  
  ระบบต้องดำเนินการชำระเงินออนไลน์สำหรับ Order ที่ผู้ใช้ยืนยัน
  โดยแสดงคิวอาร์โค้ดแบบมีเวลาจำกัด 5 นาที
  หากชำระไม่ทันเวลาที่กำหนด Order จะไม่ถูกดำเนินการต่อ

- FR-12  
  เมื่อชำระเงินสำเร็จ ระบบต้องสร้าง Order พร้อมหมายเลข Order และแสดงรายละเอียดคำสั่งซื้อให้ผู้ใช้ทราบ
  หมายเลข Order ใช้ unique ID แบบเรียงลำดับเริ่มจาก 001-999 ต่อวัน และวันใหม่จะเริ่มจาก 001 ใหม่

### Alternative Flow Requirement

- FR-06 / UC-03 Alternative Flow 3a  
  หากผู้ใช้ต้องการสั่งเครื่องดื่มเพิ่มเติม ระบบต้องให้ผู้ใช้กลับไปยังหน้าเมนูเพื่อเลือกเครื่องดื่มเพิ่มเติม และนำรายการที่เลือกกลับมาแสดงใน Order

- FR-08 / UC-03 Alternative Flow 4a  
  หากผู้ใช้แก้ไขจำนวนหรือตัวเลือกของสินค้า ระบบต้องคำนวณและแสดงยอดรวมของ Order ใหม่

### Exception Flow Requirement

- UC-03 Exception Flow 6a  
  หากการชำระเงินไม่สำเร็จ ระบบต้องไม่สร้าง Order ที่สมบูรณ์ และต้องแจ้งให้ผู้ใช้ทราบว่าการชำระเงินไม่สำเร็จ เพื่อให้ผู้ใช้สามารถดำเนินการชำระเงินใหม่ได้

- UC-03 Exception Flow 7a  
  หากสินค้าที่เลือกหมดอัตโนมัติ ระบบต้องแสดงข้อความแจ้งให้ผู้ใช้ทราบว่าสินค้าหมด และให้ผู้ใช้เปลี่ยนเมนู

## Quality Requirements
- NFR-22  
  หน้ารายการเมนูและหน้าตรวจสอบสถานะ Order ต้องตอบสนองภายใน 2 วินาที (p95) ภายใต้จำนวนผู้ใช้พร้อมกัน 100 concurrent users

- NFR-23  
  ระบบต้องสามารถบันทึก Order และรายละเอียดการสั่งซื้อได้อย่างถูกต้อง และไม่สร้าง Order ซ้ำจากการชำระเงินรายการเดียวกัน

- NFR-24  
  ระบบต้องแสดงหมายเลข Order และผลการชำระเงินให้ผู้ใช้ทราบหลังจากการชำระเงินเสร็จสิ้น

- NFR-26  
  ผู้ใช้ใหม่อย่างน้อย 8 ใน 10 คน ต้องสามารถค้นหาเมนู สร้าง Order และตรวจสอบสถานะ Order ได้โดยไม่ต้องขอความช่วยเหลือ

## Acceptance Criteria

- [ ] AC-ORDER-01 (FR-06)

  Given ผู้ใช้เปิดรายการเมนูและมีเครื่องดื่มที่เปิดขาย  
  When ผู้ใช้เลือกเครื่องดื่ม  
  Then ระบบเพิ่มเครื่องดื่มที่เลือกเข้าสู่รายการ Order

- [ ] AC-ORDER-02 (FR-07)

  Given ผู้ใช้เลือกเครื่องดื่มที่สามารถสั่งซื้อได้  
  When ผู้ใช้กำหนดจำนวนและตัวเลือกของเครื่องดื่ม  
  Then ระบบบันทึกจำนวนและตัวเลือกที่ผู้ใช้เลือกไว้ในรายการ Order
  And ตัวเลือกความหวานต้องเลือกทุกครั้ง
  And toppings และน้ำแข็งเป็นตัวเลือกเพิ่มเติมที่ไม่บังคับ
  And ถ้าไม่เลือนน้ำแข็ง ระบบถือว่าใช้การใส่น้ำแข็งปริมาณปกติ

- [ ] AC-ORDER-03 (FR-08)

  Given ผู้ใช้มีรายการเครื่องดื่มใน Order  
  When ผู้ใช้เปิดหน้าตรวจสอบ Order  
  Then ระบบแสดงชื่อเครื่องดื่ม จำนวน ราคา และยอดรวมของ Order อย่างถูกต้อง
  And แสดงราคาโปรชั่นที่ลดอยู่

- [ ] AC-ORDER-04 (FR-09)

  Given ผู้ใช้มีรายการเครื่องดื่มใน Order  
  When ผู้ใช้แก้ไขจำนวนหรือลบรายการเครื่องดื่ม  
  Then ระบบปรับปรุงรายการและคำนวณยอดรวมใหม่ให้ถูกต้อง
  And เมื่อจำนวนเป็น 0 ระบบลบรายการออกจาก Order

- [ ] AC-ORDER-05 (FR-10)

  Given ผู้ใช้ตรวจสอบรายการ Order และข้อมูลครบถ้วน  
  When ผู้ใช้กดยืนยันคำสั่งซื้อ  
  Then ระบบนำผู้ใช้เข้าสู่ขั้นตอนการชำระเงิน
  And ต้องมีรายการอย่างน้อย 1 รายการ
  And ระดับความหวานต้องเลือกแล้ว

- [ ] AC-ORDER-06 (FR-11)

  Given ผู้ใช้ยืนยันคำสั่งซื้อแล้ว  
  When ผู้ใช้ดำเนินการชำระเงินออนไลน์  
  Then ระบบแสดงคิวอาร์โค้ดแบบมีเวลาจำกัด 5 นาที
  And หากเกินเวลาที่กำหนด Order จะไม่ถูกดำเนินการต่อ

- [ ] AC-ORDER-07 (FR-12)

  Given ผู้ใช้ชำระเงินสำเร็จ  
  When ระบบได้รับผลการชำระเงิน  
  Then ระบบสร้าง Order พร้อมหมายเลข Order และแสดงรายละเอียดคำสั่งซื้อให้ผู้ใช้ทราบ
  And หมายเลข Order เป็น unique ID แบบเรียงลำดับ 001-999 ต่อวันและเริ่มใหม่ทุกวัน

- [ ] AC-ORDER-08 (UC-03 Alternative Flow 3a)

  Given ผู้ใช้กำลังตรวจสอบ Order  
  When ผู้ใช้ต้องการสั่งเครื่องดื่มเพิ่มเติม  
  Then ระบบนำผู้ใช้กลับไปยังหน้าเมนูเพื่อเลือกเครื่องดื่มเพิ่มเติม

- [ ] AC-ORDER-09 (UC-03 Alternative Flow 4a)

  Given ผู้ใช้แก้ไขจำนวนหรือตัวเลือกของเครื่องดื่ม  
  When ระบบได้รับข้อมูลที่แก้ไข  
  Then ระบบคำนวณและแสดงยอดรวมของ Order ใหม่อย่างถูกต้อง

- [ ] AC-ORDER-10 (UC-03 Exception Flow 6a)

  Given ผู้ใช้ยืนยัน Order และเข้าสู่ขั้นตอนการชำระเงิน  
  When การชำระเงินไม่สำเร็จ  
  Then ระบบไม่สร้าง Order ที่สมบูรณ์ และแสดงข้อความแจ้งว่าการชำระเงินไม่สำเร็จ

- [ ] AC-ORDER-11 (UC-03 Exception Flow 7a)

  Given ผู้ใช้เลือกสินค้าที่มีสต็อกหมดอัตโนมัติ  
  When ระบบตรวจสอบรายการสั่งซื้อ  
  Then ระบบแสดงข้อความแจ้งว่าสินค้าหมดและให้ผู้ใช้เปลี่ยนเมนู

- [ ] AC-ORDER-12 (NFR-23)

  Given ผู้ใช้ชำระเงินสำเร็จ  
  When ระบบสร้าง Order  
  Then ระบบต้องสร้าง Order เพียง 1 รายการสำหรับการชำระเงินครั้งนั้น และรายละเอียด Order ต้องถูกต้อง

## Assumptions and Open Questions

### Assumptions
- ASM-01  
  ผู้ใช้สามารถเลือกเครื่องดื่มได้เฉพาะรายการที่ร้านเปิดขาย

- ASM-02  
  ผู้ใช้ต้องกำหนดจำนวนเครื่องดื่มก่อนยืนยัน Order

- ASM-03  
  ระบบจะคำนวณยอดรวมจากราคาและจำนวนของเครื่องดื่มที่ผู้ใช้เลือก

- ASM-04  
  ผู้ใช้สามารถแก้ไขจำนวนหรือลบรายการก่อนยืนยัน Order

- ASM-05  
  การสร้าง Order จะเกิดขึ้นหลังจากการชำระเงินสำเร็จ

- ASM-06  
  หลังจากสร้าง Order สำเร็จ ระบบจะแสดงหมายเลข Order ให้ผู้ใช้

- ASM-07  
  หากการชำระเงินไม่สำเร็จ ผู้ใช้สามารถกลับมาดำเนินการชำระเงินใหม่ได้

- ASM-08  
  ระดับความหวานเป็นข้อมูลที่จำเป็นทุกครั้ง ต้องเลือกให้ครบทุกครั้งก่อนยืนยัน Order

- ASM-09  
  toppings และน้ำแข็งเป็นข้อมูลเสริม โดยน้ำแข็งถ้าไม่ได้เลือกจะใช้ค่า default คือ ใส่น้ำแข็งปริมาณปกติ

- ASM-10  
  ราคาที่แสดงคือราคาสินค้าหลังลดส่วนลดโปรชั่นที่มีอยู่และมีผลทันที

- ASM-11  
  หากมีสินค้าใน Order หมดอัตโนมัติ ระบบจะสั่งให้ผู้ใช้เปลี่ยนเมนูหรือยกเลิกรายการก่อนดำเนินการต่อ

## Quality Requirements
- NFR-22  
  หน้ารายการเมนูและหน้าตรวจสอบสถานะ Order ต้องตอบสนองภายใน 2 วินาที (p95) ภายใต้จำนวนผู้ใช้พร้อมกัน 100 concurrent users

- NFR-23  
  ระบบต้องสามารถบันทึก Order และรายละเอียดการสั่งซื้อได้อย่างถูกต้อง และไม่สร้าง Order ซ้ำจากการชำระเงินรายการเดียวกัน

- NFR-24  
  ระบบต้องแสดงหมายเลข Order และผลการชำระเงินให้ผู้ใช้ทราบหลังจากการชำระเงินเสร็จสิ้น

- NFR-26  
  ผู้ใช้ใหม่อย่างน้อย 8 ใน 10 คน ต้องสามารถค้นหาเมนู สร้าง Order และตรวจสอบสถานะ Order ได้โดยไม่ต้องขอความช่วยเหลือ

## Acceptance Criteria

- [ ] AC-ORDER-01 (FR-06)

  Given ผู้ใช้เปิดรายการเมนูและมีเครื่องดื่มที่เปิดขาย  
  When ผู้ใช้เลือกเครื่องดื่ม  
  Then ระบบเพิ่มเครื่องดื่มที่เลือกเข้าสู่รายการ Order

- [ ] AC-ORDER-02 (FR-07)

  Given ผู้ใช้เลือกเครื่องดื่มที่สามารถสั่งซื้อได้  
  When ผู้ใช้กำหนดจำนวนและตัวเลือกของเครื่องดื่ม  
  Then ระบบบันทึกจำนวนและตัวเลือกที่ผู้ใช้เลือกไว้ในรายการ Order
  And ตัวเลือกความหวานต้องเลือกทุกครั้ง
  And toppings และน้ำแข็งเป็นตัวเลือกเพิ่มเติมที่ไม่บังคับ
  And ถ้าไม่เลือนน้ำแข็ง ระบบถือว่าใช้การใส่น้ำแข็งปริมาณปกติ

- [ ] AC-ORDER-03 (FR-08)

  Given ผู้ใช้มีรายการเครื่องดื่มใน Order  
  When ผู้ใช้เปิดหน้าตรวจสอบ Order  
  Then ระบบแสดงชื่อเครื่องดื่ม จำนวน ราคา และยอดรวมของ Order อย่างถูกต้อง
  And แสดงราคาโปรชั่นที่ลดอยู่

- [ ] AC-ORDER-04 (FR-09)

  Given ผู้ใช้มีรายการเครื่องดื่มใน Order  
  When ผู้ใช้แก้ไขจำนวนหรือลบรายการเครื่องดื่ม  
  Then ระบบปรับปรุงรายการและคำนวณยอดรวมใหม่ให้ถูกต้อง
  And เมื่อจำนวนเป็น 0 ระบบลบรายการออกจาก Order

- [ ] AC-ORDER-05 (FR-10)

  Given ผู้ใช้ตรวจสอบรายการ Order และข้อมูลครบถ้วน  
  When ผู้ใช้กดยืนยันคำสั่งซื้อ  
  Then ระบบนำผู้ใช้เข้าสู่ขั้นตอนการชำระเงิน
  And ต้องมีรายการอย่างน้อย 1 รายการ
  And ระดับความหวานต้องเลือกแล้ว

- [ ] AC-ORDER-06 (FR-11)

  Given ผู้ใช้ยืนยันคำสั่งซื้อแล้ว  
  When ผู้ใช้ดำเนินการชำระเงินออนไลน์  
  Then ระบบแสดงคิวอาร์โค้ดแบบมีเวลาจำกัด 5 นาที
  And หากเกินเวลาที่กำหนด Order จะไม่ถูกดำเนินการต่อ

- [ ] AC-ORDER-07 (FR-12)

  Given ผู้ใช้ชำระเงินสำเร็จ  
  When ระบบได้รับผลการชำระเงิน  
  Then ระบบสร้าง Order พร้อมหมายเลข Order และแสดงรายละเอียดคำสั่งซื้อให้ผู้ใช้ทราบ
  And หมายเลข Order เป็น unique ID แบบเรียงลำดับ 001-999 ต่อวันและเริ่มใหม่ทุกวัน

- [ ] AC-ORDER-08 (UC-03 Alternative Flow 3a)

  Given ผู้ใช้กำลังตรวจสอบ Order  
  When ผู้ใช้ต้องการสั่งเครื่องดื่มเพิ่มเติม  
  Then ระบบนำผู้ใช้กลับไปยังหน้าเมนูเพื่อเลือกเครื่องดื่มเพิ่มเติม

- [ ] AC-ORDER-09 (UC-03 Alternative Flow 4a)

  Given ผู้ใช้แก้ไขจำนวนหรือตัวเลือกของเครื่องดื่ม  
  When ระบบได้รับข้อมูลที่แก้ไข  
  Then ระบบคำนวณและแสดงยอดรวมของ Order ใหม่อย่างถูกต้อง

- [ ] AC-ORDER-10 (UC-03 Exception Flow 6a)

  Given ผู้ใช้ยืนยัน Order และเข้าสู่ขั้นตอนการชำระเงิน  
  When การชำระเงินไม่สำเร็จ  
  Then ระบบไม่สร้าง Order ที่สมบูรณ์ และแสดงข้อความแจ้งว่าการชำระเงินไม่สำเร็จ

- [ ] AC-ORDER-11 (UC-03 Exception Flow 7a)

  Given ผู้ใช้เลือกสินค้าที่มีสต็อกหมดอัตโนมัติ  
  When ระบบตรวจสอบรายการสั่งซื้อ  
  Then ระบบแสดงข้อความแจ้งว่าสินค้าหมดและให้ผู้ใช้เปลี่ยนเมนู

- [ ] AC-ORDER-12 (NFR-23)

  Given ผู้ใช้ชำระเงินสำเร็จ  
  When ระบบสร้าง Order  
  Then ระบบต้องสร้าง Order เพียง 1 รายการสำหรับการชำระเงินครั้งนั้น และรายละเอียด Order ต้องถูกต้อง

## Assumptions and Open Questions

### Assumptions
- ASM-01  
  ผู้ใช้สามารถเลือกเครื่องดื่มได้เฉพาะรายการที่ร้านเปิดขาย

- ASM-02  
  ผู้ใช้ต้องกำหนดจำนวนเครื่องดื่มก่อนยืนยัน Order

- ASM-03  
  ระบบจะคำนวณยอดรวมจากราคาและจำนวนของเครื่องดื่มที่ผู้ใช้เลือก

- ASM-04  
  ผู้ใช้สามารถแก้ไขจำนวนหรือลบรายการก่อนยืนยัน Order

- ASM-05  
  การสร้าง Order จะเกิดขึ้นหลังจากการชำระเงินสำเร็จ

- ASM-06  
  หลังจากสร้าง Order สำเร็จ ระบบจะแสดงหมายเลข Order ให้ผู้ใช้

- ASM-07  
  หากการชำระเงินไม่สำเร็จ ผู้ใช้สามารถกลับมาดำเนินการชำระเงินใหม่ได้

- ASM-08  
  ระดับความหวานเป็นข้อมูลที่จำเป็นทุกครั้ง ต้องเลือกให้ครบทุกครั้งก่อนยืนยัน Order

- ASM-09  
  toppings และน้ำแข็งเป็นข้อมูลเสริม โดยน้ำแข็งถ้าไม่ได้เลือกจะใช้ค่า default คือ ใส่น้ำแข็งปริมาณปกติ

- ASM-10  
  ราคาที่แสดงคือราคาสินค้าหลังลดส่วนลดโปรชั่นที่มีอยู่และมีผลทันที

- ASM-11  
  หากมีสินค้าใน Order หมดอัตโนมัติ ระบบจะสั่งให้ผู้ใช้เปลี่ยนเมนูหรือยกเลิกรายการก่อนดำเนินการต่อ

### Open Questions
- ช่องทางการชำระเงินออนไลน์ที่ระบบจะรองรับมีอะไรบ้าง
- จำเป็นต้องให้ผู้ใช้กรอกข้อมูลส่วนตัวก่อนชำระเงินหรือไม่
- Order สามารถสั่งเครื่องดื่มหลายรายการที่มีตัวเลือกแตกต่างกันได้หรือไม่
- โปรโมชั่นจาก UC-01 จะถูกนำมาคำนวณใน Order โดยอัตโนมัติหรือไม่
- หากสินค้าใน Order หมดสต็อกระหว่างการสั่งซื้อ ระบบจะดำเนินการอย่างไร
