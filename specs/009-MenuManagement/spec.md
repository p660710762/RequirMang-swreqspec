# Feature: จัดการเมนู ราคา โปรโมชั่น และสถานะสินค้า (Menu & Product Management)
Spec ID: SPEC-MENU-MANAGEMENT-001 | Source: SRS v0.1 ข้อ 3.9 (FR-MENU-MANAGEMENT) | Use case: UC-09  
Owner: <ทีม/คน> | Status: Draft v4 | Updated: 2569-10-26
Depends on: SPEC-MENU-001 | Reviewed by: -

## Goal
ผู้ดูแลระบบ (Admin) สามารถจัดการข้อมูลเมนู ราคา โปรโมชั่น และสถานะสินค้า
ให้เป็นข้อมูลปัจจุบันและถูกต้อง เพื่อให้ข้อมูลที่แสดงแก่ลูกค้าสอดคล้องกับข้อมูล
ที่ใช้ในการให้บริการจริง

## Scope
### In scope
- ดูรายการเมนูที่มีอยู่ในระบบ
- เพิ่มเมนูใหม่
- แก้ไขข้อมูลเมนู
- ลบเมนูออกจากระบบถาวรเมื่อจำเป็น
- แก้ไขราคาเมนู
- จัดการรายละเอียดเมนู
- จัดการโปรโมชั่นในหน้าเดียวกับเมนู
- เปลี่ยนสถานะสินค้า
- กำหนดสถานะสินค้าเป็น “หมด”
- บันทึกข้อมูลที่มีการเปลี่ยนแปลง
- แสดงข้อมูลล่าสุดหลังจากบันทึกสำเร็จ
- คงข้อมูลเมนูที่จำเป็นไว้เพื่อให้ Order เดิมยังสามารถตรวจสอบได้

### Out of scope
- การสร้าง Order
- การชำระเงิน
- การติดตามสถานะ Order
- การแจ้งเตือนลูกค้าผ่าน LINE
- การจัดการ Order ของพนักงาน
- การดูรายงานยอดขายและสถิติ
- การจัดการบัญชีผู้ใช้งานและสิทธิ์ของ Admin

## Constraints
- ผู้ใช้งานต้องเข้าสู่ระบบและมีสิทธิ์เป็น Admin ก่อนจัดการข้อมูลเมนู
- ระบบต้องตรวจสอบข้อมูลที่จำเป็นก่อนบันทึก ได้แก่ ชื่อ ราคา และสถานะ ส่วนรายละเอียดและรูปภาพเป็น optional
- Admin สามารถลบเมนูออกจากระบบถาวรได้ แต่เมนูที่ถูกลบต้องหายจาก catalog ปัจจุบัน และต้องรักษา snapshot สำหรับ Order เก่าไว้ โดยไม่แสดงเมนูที่ถูกลบให้ลูกค้าเห็น
- การลบเมนูถาวรและการเปลี่ยนสถานะเป็น “หมด” เป็น 2 action ที่แยกกัน
- โปรโมชั่นต้องระบุวันเริ่มต้นและวันสิ้นสุด โดยทั้งสองค่าเป็น ISO 8601 datetime ที่มี timezone และวันสิ้นสุดต้องไม่อยู่ก่อนวันเริ่มต้น
- วันเริ่มต้นและวันสิ้นสุดของโปรโมชั่นต้องไม่เป็นวันหรือเวลาที่ผ่านมาแล้ว โดยหน้าจอต้องไม่ให้เลือกค่าก่อนเวลาปัจจุบัน
- ช่องวันเริ่มต้นและวันสิ้นสุดต้องแสดงผลแบบภาษาไทยและปี พ.ศ. ในหน้าจอ พร้อมรองรับการเลือกผ่าน date-time picker ส่วนค่าที่ส่งไปยังระบบต้องเป็น ISO 8601 datetime พร้อม timezone และใช้ปี ค.ศ. ตามมาตรฐาน API
- ส่วนลดโปรโมชั่นเป็นจำนวนเงิน ต้องไม่ติดลบและต้องไม่มากกว่าราคาเมนู โดยราคาที่แสดงหลังลดคำนวณจากราคาเมนูลบด้วยส่วนลด
- การเปลี่ยนสถานะเมนูทั้งเป็น “หมด” และ “เปิดขาย” ต้องยืนยันก่อนบันทึก
- เมนูมีสถานะเพียง 2 แบบ: “เปิดขาย” และ “หมด”
- “หมด” หมายถึงเมนูไม่เปิดขายชั่วคราว แต่เมนูยังอยู่ในระบบ
- เมนูที่ถูกกำหนดสถานะ “หมด” ต้องไม่สามารถถูกสั่งซื้อจากหน้าลูกค้าได้
- ข้อมูลราคาและรายละเอียดที่บันทึกต้องเป็นข้อมูลล่าสุดที่ระบบนำไปแสดงแก่ลูกค้า
- การเปลี่ยนแปลงเมนูมีผลเฉพาะคำสั่งซื้อใหม่ ส่วน Order เดิมต้องคงค่าสินค้าดั้งเดิมไว้
- การบันทึกข้อมูลเมนูต้องเป็นแบบทั้งหมดหรือไม่เลย และเมื่อบันทึกล้มเหลวต้อง rollback ทั้งหมดเพื่อคง state เดิม
- ข้อมูลที่เก็บเพื่อคงความถูกต้องของ Order เก่าจำกัดเฉพาะ Order snapshot และ menu history ก่อนการแก้ไข ไม่รวม record ปัจจุบัน

## Requirements
- FR-42  
  Admin สามารถเปิดดูรายการเมนูและข้อมูลที่เกี่ยวข้องได้

- FR-43  
  Admin สามารถเพิ่มเมนูใหม่เข้าสู่ระบบ โดยต้องระบุข้อมูลที่จำเป็นของเมนูให้ครบถ้วน
  ข้อมูลขั้นต่ำที่ต้องมี ได้แก่ ชื่อ ราคา และสถานะ ส่วนรายละเอียดและรูปภาพเป็น optional

- FR-44  
  Admin สามารถแก้ไขข้อมูลเมนู ราคา รายละเอียด และโปรโมชั่นที่เกี่ยวข้องได้
  การจัดการโปรโมชั่นอยู่ในหน้าเดียวกันกับเมนู โดยต้องระบุวันเริ่มต้นและวันสิ้นสุดในรูปแบบ ISO 8601 ที่มี timezone และวันสิ้นสุดต้องไม่อยู่ก่อนวันเริ่มต้น

- FR-45  
  Admin สามารถเปลี่ยนสถานะของสินค้าได้
  สถานะที่รองรับมีเพียง “เปิดขาย” และ “หมด” เท่านั้น

- FR-46  
  ระบบต้องตรวจสอบข้อมูลที่จำเป็นก่อนบันทึก ได้แก่ ชื่อ ราคา และสถานะ โดยรายละเอียดและรูปภาพเป็น optional

- FR-47  
  เมื่อ Admin ยืนยันการเปลี่ยนแปลง ระบบต้องบันทึกข้อมูลใหม่และแสดงข้อมูลล่าสุด

- FR-48  
  เมื่อเมนูถูกเปลี่ยนสถานะเป็น “หมด” ระบบต้องไม่อนุญาตให้ลูกค้าสั่งเมนูดังกล่าว
  “หมด” หมายถึงไม่เปิดขายชั่วคราว แต่เมนูยังอยู่ในระบบ

- FR-49  
  ระบบต้องเก็บข้อมูลเดิมหรือประวัติที่จำเป็นของเมนูที่ถูกแก้ไข เพื่อไม่ให้กระทบข้อมูล Order ที่เกิดขึ้นก่อนหน้า
  การเปลี่ยนแปลงเมนูมีผลเฉพาะคำสั่งซื้อใหม่เท่านั้น ส่วน Order เดิมต้องคงค่าสินค้าดั้งเดิมไว้
  ข้อมูลที่เก็บไว้เป็น Order snapshot และ menu history ที่จำเป็นเท่านั้น โดยไม่รวม record ปัจจุบัน
  การลบเมนูออกจาก catalog ปัจจุบันต้องไม่ทำให้ Order snapshot เดิมสูญหาย

### Alternative Flow Requirement

- FR-43 / UC-09 Alternative Flow 3a  
  หาก Admin เลือกเมนูที่ไม่จำหน่ายหรือไม่ต้องการใช้งาน ระบบต้องยืนยันก่อนดำเนินการ และไม่อนุญาตให้เมนูดังกล่าวแสดงเป็นเมนูที่เปิดขาย

- FR-45 / UC-09 Alternative Flow 4a  
  หาก Admin เปลี่ยนสถานะสินค้าเป็น “หมด” ระบบต้องบันทึกสถานะใหม่และไม่อนุญาตให้ลูกค้าสั่งซื้อสินค้านั้น

### Exception Flow Requirement

- UC-09 Exception Flow 6a  
  หากข้อมูลที่ Admin กรอกไม่ครบถ้วนหรือไม่ถูกต้อง ระบบต้องไม่บันทึกข้อมูล และแจ้งให้ Admin แก้ไขข้อมูล

- UC-09 Exception Flow 7a  
  หากระบบไม่สามารถบันทึกข้อมูลได้ ระบบต้องแจ้งให้ Admin ทราบว่าไม่สามารถบันทึกข้อมูลได้ และต้องไม่แสดงข้อมูลใหม่เป็นข้อมูลที่บันทึกสำเร็จ

## Quality Requirements
- NFR-SEC-05  
  เฉพาะ Admin ที่ได้รับอนุญาตเท่านั้นที่สามารถเพิ่ม แก้ไข หรือลบข้อมูลเมนู ราคา โปรโมชั่น และสถานะสินค้าได้

- NFR-REL-08  
  ข้อมูลเมนู ราคา โปรโมชั่น และสถานะสินค้าต้องถูกบันทึกอย่างถูกต้อง และไม่ทำให้ข้อมูลเดิมสูญหายจากข้อผิดพลาดระหว่างการบันทึก

- NFR-REL-09  
  การเปลี่ยนสถานะสินค้าเป็น “หมด” ต้องไม่กระทบข้อมูล Order ที่สร้างไว้ก่อนหน้า

- NFR-USE-03  
  ระบบต้องแสดงข้อมูลเมนู ราคา และสถานะสินค้าอย่างชัดเจน เพื่อให้ Admin สามารถตรวจสอบและแก้ไขข้อมูลได้ถูกต้อง

## Acceptance Criteria

- [ ] AC-MENU-MGMT-01 (FR-42)

  Given Admin มีสิทธิ์จัดการข้อมูลเมนู  
  When Admin เปิดหน้าจัดการเมนู  
  Then ระบบแสดงรายการเมนูและข้อมูลที่เกี่ยวข้อง

- [ ] AC-MENU-MGMT-02 (FR-43)

  Given Admin อยู่ในหน้าจัดการเมนู  
  When Admin เพิ่มข้อมูลเมนูใหม่และกรอกข้อมูลที่จำเป็นครบถ้วน  
  Then ระบบบันทึกเมนูใหม่และแสดงเมนูดังกล่าวในรายการ

- [ ] AC-MENU-MGMT-03 (FR-44)

  Given มีเมนูอยู่ในระบบ  
  When Admin แก้ไขราคา รายละเอียด หรือข้อมูลที่เกี่ยวข้องและกดบันทึก  
  Then ระบบบันทึกข้อมูลใหม่และแสดงข้อมูลล่าสุด

- [ ] AC-MENU-MGMT-04 (FR-45)

  Given มีเมนูอยู่ในระบบ  
  When Admin เปลี่ยนสถานะของสินค้า  
  Then ระบบบันทึกและแสดงสถานะใหม่ของสินค้า

- [ ] AC-MENU-MGMT-05 (FR-46)

  Given Admin กรอกข้อมูลเพื่อเพิ่มหรือแก้ไขเมนู  
  When Admin กดบันทึก  
  Then ระบบตรวจสอบข้อมูลก่อนบันทึก และแจ้งข้อผิดพลาดหากข้อมูลไม่ถูกต้อง

- [ ] AC-MENU-MGMT-06 (FR-47)

  Given Admin กรอกข้อมูลถูกต้องครบถ้วน  
  When Admin ยืนยันการเปลี่ยนแปลง  
  Then ระบบบันทึกข้อมูลสำเร็จและแสดงข้อมูลล่าสุด

- [ ] AC-MENU-MGMT-07 (FR-48)

  Given Admin เปลี่ยนสถานะเมนูเป็น “หมด”  
  When ลูกค้าเปิดหน้ารายการเมนู  
  Then ระบบแสดงสถานะ “หมด” และไม่อนุญาตให้ลูกค้าสั่งเมนูดังกล่าว

- [ ] AC-MENU-MGMT-08 (FR-49)

  Given มี Order ที่เกิดขึ้นก่อนการแก้ไขข้อมูลเมนู  
  When Admin แก้ไขราคา หรือสถานะของเมนู  
  Then ข้อมูล Order เดิมต้องยังคงสามารถตรวจสอบได้และไม่ถูกเปลี่ยนแปลงโดยอัตโนมัติ

- [ ] AC-MENU-MGMT-09 (UC-09 Alternative Flow 3a)

  Given Admin เลือกเมนูที่ไม่จำหน่ายหรือไม่ต้องการใช้งาน  
  When Admin ยืนยันการดำเนินการ  
  Then ระบบเปลี่ยนเมนูดังกล่าวให้อยู่ในสถานะที่ไม่เปิดขาย และไม่แสดงเป็นเมนูที่สามารถสั่งซื้อได้

- [ ] AC-MENU-MGMT-10 (UC-09 Alternative Flow 4a)

  Given Admin เลือกเมนูที่เปิดขายอยู่  
  When Admin เปลี่ยนสถานะเป็น “หมด”  
  Then ระบบบันทึกสถานะ “หมด” และไม่อนุญาตให้ลูกค้าสั่งเมนูดังกล่าว

- [ ] AC-MENU-MGMT-11 (UC-09 Exception Flow 6a)

  Given Admin กรอกข้อมูลเมนูไม่ครบถ้วนหรือไม่ถูกต้อง  
  When Admin กดบันทึก  
  Then ระบบไม่บันทึกข้อมูล และแจ้งให้ Admin แก้ไขข้อมูล

- [ ] AC-MENU-MGMT-12 (UC-09 Exception Flow 7a)

  Given Admin กรอกข้อมูลถูกต้องและกดบันทึก  
  When ระบบไม่สามารถบันทึกข้อมูลได้  
  Then ระบบแจ้งให้ Admin ทราบว่าไม่สามารถบันทึกข้อมูลได้ และไม่แสดงข้อมูลใหม่เป็นข้อมูลที่บันทึกสำเร็จ

- [ ] AC-MENU-MGMT-13 (NFR-SEC-05)

  Given ผู้ใช้งานไม่มีสิทธิ์ Admin  
  When ผู้ใช้งานพยายามเพิ่ม แก้ไข หรือลบข้อมูลเมนู  
  Then ระบบไม่อนุญาตให้ดำเนินการ

- [ ] AC-MENU-MGMT-14 (NFR-REL-09)

  Given มี Order เดิมที่ใช้เมนูที่ภายหลังถูกเปลี่ยนสถานะเป็น “หมด”  
  When Admin เปลี่ยนสถานะเมนู  
  Then Order เดิมยังคงมีข้อมูลเดิมและสามารถตรวจสอบได้

- [ ] AC-MENU-MGMT-15 (FR-44)

  Given Admin กำหนดวันเริ่มต้นและวันสิ้นสุดของโปรโมชั่น

  When วันใดวันหนึ่งขาดหาย รูปแบบไม่ใช่ ISO 8601 datetime ที่มี timezone หรือวันสิ้นสุดอยู่ก่อนวันเริ่มต้น

  Then ระบบปฏิเสธข้อมูลโปรโมชั่นและไม่บันทึกการเปลี่ยนแปลง

## Assumptions and Open Questions

### Assumptions
- ASM-01  
  ผู้ใช้งานที่ดำเนินการจัดการเมนูเป็น Admin ที่เข้าสู่ระบบและได้รับสิทธิ์แล้ว

- ASM-02  
  เมนูแต่ละรายการต้องมีชื่อ ราคา และสถานะ; รายละเอียดและรูปภาพเป็น optional

- ASM-03  
  สถานะ “หมด” หมายถึงเมนูไม่เปิดขายชั่วคราว แต่เมนูยังอยู่ในระบบ

- ASM-04  
  การแก้ไขราคาใหม่จะมีผลกับการสั่งซื้อใหม่หลังจากบันทึกข้อมูลสำเร็จ และ Order เดิมต้องคงค่าสินค้าดั้งเดิมไว้

- ASM-05  
  ข้อมูล Order ที่เกิดขึ้นก่อนการแก้ไขเมนูต้องไม่ถูกแก้ไขตามข้อมูลเมนูปัจจุบัน

- ASM-06  
  ระบบสามารถแสดงข้อมูลเมนูที่ Admin แก้ไขสำเร็จแก่ลูกค้าได้

- ASM-07  
  การจัดการโปรโมชั่นอยู่ในหน้าเดียวกันกับเมนู

- ASM-08  
  ข้อมูลที่เก็บไว้เพื่อคงความถูกต้องของ Order เก่าเป็นข้อมูลที่จำเป็นเท่านั้น

### Additional Assumptions
- ASM-09
  เมนูที่ Admin ลบถาวรต้องหายจาก catalog ปัจจุบัน แต่ข้อมูล snapshot ที่จำเป็นของ Order เก่าต้องยังตรวจสอบได้

- ASM-10
  ข้อมูลที่จำเป็นก่อนบันทึกเมนูคือชื่อ ราคา และสถานะ ส่วนรายละเอียดและรูปภาพเป็น optional

- ASM-11
  การบันทึกต้องเป็นแบบทั้งหมดหรือไม่เลย และข้อมูลเดิมต้องไม่เปลี่ยนเมื่อเกิดความล้มเหลวระหว่างบันทึก

- ASM-12
  การลบเมนูถาวรและการเปลี่ยนสถานะเป็น “หมด” เป็นคนละ action

- ASM-13
  ข้อมูลย้อนหลังที่จำเป็นมีเฉพาะ Order snapshot และ menu history ก่อนการแก้ไข ไม่รวม record ปัจจุบัน

- ASM-14
  วันเริ่มต้นและวันสิ้นสุดของโปรโมชั่นเป็นข้อมูลบังคับ ใช้รูปแบบ ISO 8601 datetime ที่มี timezone และวันสิ้นสุดต้องไม่อยู่ก่อนวันเริ่มต้น
