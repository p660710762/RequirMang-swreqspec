# Feature: สมัครสมาชิก / เข้าสู่ระบบ (Register & Login)
Spec ID: SPEC-ACCOUNT-001 | Source: SRS v0.1 ข้อ 3.2 | Use case: UC-02
Owner: <ทีม/คน> | Status: Draft v4 | Updated: 2569-10-28
Depends on: - | Reviewed by: -

## Goal
นักศึกษา / ลูกค้า (เป็นผู้ใช้ทั่วไปของระบบเดียวกัน) สามารถสมัครสมาชิกใหม่หรือเข้าสู่ระบบด้วยบัญชีที่มีอยู่
เพื่อใช้งานระบบสั่งซื้อเครื่องดื่มออนไลน์และตรวจสอบประวัติการสั่งซื้อ
โดยไม่จำเป็นต้องมีบทบาทแยกกันในการสมัครหรือเข้าสู่ระบบ

## Scope

### In scope
- สมัครสมาชิกด้วย Email หรือเบอร์โทรศัพท์อย่างน้อยหนึ่งช่องและข้อมูลที่ระบบกำหนด
- ตรวจสอบความครบถ้วนและความถูกต้องของข้อมูลสมัครสมาชิก
- ตรวจสอบข้อมูลบัญชีซ้ำ
- เข้าสู่ระบบด้วยข้อมูลบัญชีที่มีอยู่
- ตรวจสอบข้อมูลเข้าสู่ระบบ
- แสดงข้อความแจ้งเตือนเมื่อเข้าสู่ระบบไม่สำเร็จ
- ให้ลูกค้าเลือกเชื่อมต่อบัญชี LINE
- จำลองการเชื่อมต่อ LINE และเก็บ Mock LINE User ID ใน Browser Memory เมื่อเชื่อมต่อสำเร็จ

### Out of scope
- การจัดการข้อมูลส่วนตัวหลังเข้าสู่ระบบ
- การเปลี่ยนรหัสผ่าน
- การส่งแจ้งเตือน Order ผ่าน LINE
- การจัดการ LINE Notification Service
- การจัดการบัญชีของพนักงานและผู้ดูแลระบบ

## Constraints
- ลูกค้าต้องสามารถเข้าถึงหน้าสมัครสมาชิกหรือเข้าสู่ระบบได้
- Email หรือเบอร์โทรศัพท์ต้องไม่ซ้ำกับบัญชีที่มีอยู่ในระบบ
- ผู้ใช้สามารถกรอก Email หรือเบอร์โทรศัพท์อย่างน้อยหนึ่งช่อง โดยไม่จำเป็นต้องกรอกทั้งคู่
- Password ต้องไม่เป็นค่าว่าง และสำหรับการเข้าสู่ระบบ รหัสผ่านที่กรอกต้องตรงกับรหัสผ่านของบัญชี Mock ที่ลงทะเบียนไว้ จึงจะสามารถเข้าสู่ระบบได้
- การเชื่อมต่อ LINE เป็นทางเลือก ไม่บังคับต่อการสมัครสมาชิกหรือเข้าสู่ระบบ
- ระบบต้องไม่จัดเก็บ Password ของบัญชี LINE
- ระบบต้องสามารถเชื่อมโยง Mock LINE User ID `mock-line-user-001` กับบัญชีลูกค้าที่ Login/Register สำเร็จใน Browser Memory ได้อย่างถูกต้อง
- ข้อมูลส่วนบุคคลที่เกี่ยวกับบัญชี เช่น ชื่อ อีเมล เบอร์โทรศัพท์ ต้องมีการ login ก่อนถึงจะเข้าถึงได้

## Requirements
- FR-01
  ระบบต้องสามารถให้ลูกค้าสมัครสมาชิกโดยกรอก Email หรือเบอร์โทรศัพท์อย่างน้อยหนึ่งช่อง พร้อมรหัสผ่านที่ไม่ว่างตามที่ระบบกำหนด

- FR-02
  ระบบต้องแสดงแบบฟอร์มสำหรับสมัครสมาชิกหรือเข้าสู่ระบบบนหน้าเดียวกัน
  โดยมีฟอร์ม login อยู่ด้านบนพร้อมปุ่มเข้าสู่ระบบ
  และด้านล่างมีปุ่มสมัครสมาชิกแยกอีกปุ่ม
  ระบบต้องตรวจสอบความครบถ้วน ความถูกต้อง และข้อมูลซ้ำก่อนสร้างบัญชีผู้ใช้

- FR-03
  ระบบต้องสามารถตรวจสอบข้อมูลบัญชีและอนุญาตให้ลูกค้าเข้าสู่ระบบ
  เมื่อกรอก Email หรือเบอร์โทรศัพท์ที่ลงทะเบียนไว้
  พร้อมรหัสผ่านที่ตรงกับบัญชี Mock ดังกล่าว
  โดยผู้ใช้สามารถเลือกใช้ Email หรือเบอร์โทรศัพท์อย่างใดอย่างหนึ่ง
  ในการเข้าสู่ระบบได้

- FR-04
  เมื่อข้อมูลเข้าสู่ระบบไม่ถูกต้อง ระบบต้องแจ้งเตือน “กรุณากรอกข้อมูลให้ถูกต้อง” และไม่อนุญาตให้เข้าสู่ระบบ
  หาก Email หรือเบอร์โทรศัพท์ถูกใช้สมัครสมาชิกแล้ว ระบบต้องปฏิเสธทันทีและแสดงข้อความ “อีเมล/เบอร์โทรศัพท์นี้ถูกใช้งานแล้ว” โดยไม่สร้างบัญชีซ้ำ

- FR-05
  ระบบต้องสามารถให้ลูกค้าเลือกเชื่อมต่อบัญชีผู้ใช้กับ LINE เพื่อรับการแจ้งเตือน Order
  โดย Prototype จำลองผลสำเร็จและล้มเหลวด้วย HTML/CSS/Vanilla JavaScript
  โดยไม่เชื่อมต่อ LINE API จริง

- FR-06
  เมื่อเชื่อมต่อ LINE สำเร็จ ระบบ Prototype ต้องเก็บ Mock LINE User ID
  `mock-line-user-001` ใน Browser Memory และผูกกับบัญชีลูกค้าที่ Login/Register สำเร็จ
  โดยแสดงสถานะเชื่อมต่อสำเร็จใน UI
  และเมื่อข้อมูลถูกต้อง ระบบต้องสร้างบัญชีและถือว่าผ่านการยืนยันบัญชีผู้ใช้ แล้วอนุญาตให้เข้าสู่ระบบได้ทันที
  หากเชื่อมต่อไม่สำเร็จต้องไม่สร้างความสัมพันธ์ใหม่กับ LINE และยังใช้งาน Prototype ต่อได้

### Alternative Flow Requirement

- FR-05 / UC-02 Alternative Flow 7a
  หากลูกค้าเลือกเชื่อมต่อ LINE Prototype ต้องจำลองการเชื่อมต่อสำเร็จ
  และบันทึก Mock LINE User ID `mock-line-user-001` ใน Browser Memory
  เมื่อมีบัญชีที่ Login/Register สำเร็จแล้ว

- FR-05 / UC-02 Alternative Flow 7b
  หากลูกค้าไม่ต้องการเชื่อมต่อ LINE ระบบต้องให้ลูกค้าใช้งานระบบต่อได้ตามปกติ

### Exception Flow Requirement

- UC-02 Exception Flow 4a
  หากข้อมูลเข้าสู่ระบบไม่ถูกต้อง ระบบต้องไม่อนุญาตให้เข้าสู่ระบบและแสดงข้อความแจ้งเตือน

- UC-02 Exception Flow 4b
  หาก Email หรือเบอร์โทรศัพท์ถูกใช้สมัครแล้ว ระบบต้องไม่สร้างบัญชีซ้ำและแจ้งลูกค้า

- UC-02 Exception Flow 7c
  หากไม่สามารถเชื่อมต่อ LINE ได้ ระบบ Prototype ต้องไม่สร้างความสัมพันธ์ใหม่กับ LINE
  และต้องไม่ทำให้การสมัครสมาชิกหรือเข้าสู่ระบบล้มเหลว

## Quality Requirements
- NFR-SEC-01
  ระบบต้องป้องกันข้อมูลบัญชีและตรวจสอบสิทธิ์ก่อนอนุญาตให้เข้าถึงข้อมูลส่วนบุคคลที่เกี่ยวกับบัญชี เช่น ชื่อ อีเมล เบอร์โทรศัพท์
  โดยต้องมีการ login ก่อนถึงจะเข้าถึงข้อมูลดังกล่าวได้
  รวมถึงต้องไม่จัดเก็บ Password ของบัญชี LINE

- NFR-REL-01
  หากการเชื่อมต่อ LINE ล้มเหลว ต้องไม่ส่งผลกระทบต่อการสมัครสมาชิกหรือการเข้าสู่ระบบ

- NFR-USE-01
  ระบบต้องแสดงขั้นตอนสมัครสมาชิก เข้าสู่ระบบ และการเชื่อมต่อ LINE อย่างชัดเจน

## Acceptance Criteria

- [ ] AC-ACCOUNT-01 (FR-01 / FR-02)

  Given ลูกค้ากรอกข้อมูลสมัครสมาชิกถูกต้องและครบถ้วน
  When ลูกค้ายืนยันการสมัครสมาชิก
  Then ระบบสร้างบัญชีและให้ลูกค้าสามารถเข้าสู่ระบบได้

- [ ] AC-ACCOUNT-02 (FR-03)

  Given ลูกค้ามีบัญชีและกรอกข้อมูลเข้าสู่ระบบถูกต้อง
  When ลูกค้ายืนยันการเข้าสู่ระบบ
  Then ระบบอนุญาตให้ลูกค้าเข้าสู่ระบบได้

- [ ] AC-ACCOUNT-03 (FR-04)

  Given ลูกค้ากรอกข้อมูลเข้าสู่ระบบไม่ถูกต้อง
  When ลูกค้ายืนยันการเข้าสู่ระบบ
  Then ระบบปฏิเสธการเข้าสู่ระบบและแสดงข้อความแจ้งเตือน

- [ ] AC-ACCOUNT-04 (FR-05 / FR-06)

  Given ลูกค้า Login/Register สำเร็จและเลือกเชื่อมต่อ LINE
  When การเชื่อมต่อ LINE สำเร็จ
  Then Prototype แสดงสถานะเชื่อมต่อสำเร็จและเก็บ Mock LINE User ID `mock-line-user-001`
  ใน Browser Memory โดยผูกกับบัญชีลูกค้า

- [ ] AC-ACCOUNT-05 (UC-02 Alternative Flow 7b)

  Given ลูกค้าไม่ต้องการเชื่อมต่อ LINE
  When ลูกค้าเลือกข้ามขั้นตอนการเชื่อมต่อ LINE
  Then ระบบให้ลูกค้าใช้งานระบบต่อได้ตามปกติ

- [ ] AC-ACCOUNT-06 (UC-02 Exception Flow 7c)

  Given ลูกค้าเลือกเชื่อมต่อ LINE
  When ระบบไม่สามารถเชื่อมต่อ LINE ได้
  Then ระบบไม่บันทึก LINE User ID และลูกค้ายังคงสามารถใช้งานระบบได้

## Assumptions and Open Questions

### Assumptions
- ลูกค้าสามารถสมัครสมาชิกและเข้าสู่ระบบได้โดยไม่จำเป็นต้องเชื่อมต่อ LINE
- นักศึกษาและลูกค้าเป็นผู้ใช้ทั่วไปแบบเดียวกัน และใช้ระบบสมัคร/เข้าสู่ระบบร่วมกัน
- การเชื่อมต่อ LINE เป็นฟังก์ชันเสริมสำหรับการรับแจ้งเตือน Order
- UC-06 เป็น Use Case ที่รับผิดชอบการส่งแจ้งเตือนผ่าน LINE
- LINE User ID ที่บันทึกในระบบใช้สำหรับระบุผู้รับการแจ้งเตือน
- ข้อมูลส่วนบุคคลที่ระบุในระบบคือข้อมูลบัญชีพื้นฐาน เช่น ชื่อ อีเมล เบอร์โทรศัพท์ และต้องมีการ login ก่อนถึงจะเข้าถึงได้

### Open Questions และคำตอบของทีม
- Q-01: ใช้ Mock LINE Connection จำลองการเชื่อมต่อสำเร็จ/ล้มเหลวด้วย HTML/CSS/Vanilla JavaScript
  เก็บ Mock LINE User ID `mock-line-user-001` เฉพาะใน Browser Memory
  และผูกกับบัญชีที่ Login/Register สำเร็จเท่านั้น
- Q-02: ไม่รองรับการยกเลิกการเชื่อม LINE ใน Release นี้ เลื่อนไป Release ถัดไป
- Q-03: ไม่รองรับการเปลี่ยนบัญชี LINE ใน Release นี้ เลื่อนไป Release ถัดไป
