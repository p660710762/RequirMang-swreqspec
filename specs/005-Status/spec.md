# Feature: ติดตามสถานะ Order (Order Status Tracking)
Spec ID: SPEC-ORDER-STATUS-001 | Source: SRS v0.1 ข้อ 3.5 (FR-ORDER-STATUS) | Use case: UC-05  
Owner: <ทีม/คน> | Status: Draft v4 | Updated: 2569-10-28
Depends on: SPEC-ORDER-001, SPEC-PAYMENT-001 | Reviewed by: -

## Goal
นักศึกษา / ลูกค้า สามารถตรวจสอบสถานะล่าสุดของ Order ของตนเองได้
เพื่อให้ทราบว่า Order อยู่ในขั้นตอนใด และสามารถติดตามความคืบหน้าของการจัดเตรียมเครื่องดื่ม
ตั้งแต่รอรับ Order จนถึงพร้อมรับสินค้า / รับสินค้าแล้ว

## Scope
### In scope
- ดูรายการ Order ของตนเอง
- เลือก Order ที่ต้องการติดตาม
- ดูรายละเอียดของ Order
- แสดงสถานะล่าสุดของ Order
- แสดงสถานะการดำเนินงานของ Order ตามลำดับขั้น
- รองรับการติดตาม Order หลายรายการ
- แจ้งให้ผู้ใช้ลองโหลดข้อมูลใหม่เมื่อไม่สามารถโหลดสถานะได้

### Out of scope
- การสร้าง Order
- การแก้ไขรายการสินค้าใน Order
- การชำระเงิน
- การยกเลิก Order
- การเปลี่ยนสถานะ Order โดยลูกค้า
- การจัดการ Order ของพนักงาน
- การจัดการเมนู ราคา โปรโมชั่น และสถานะสินค้า
- การส่งแจ้งเตือนเมื่อสถานะ Order เปลี่ยนแปลง
- การดูรายงานยอดขายและสถิติ

## Constraints
- ผู้ใช้ต้องมี Order อยู่ในระบบก่อนจึงสามารถติดตามสถานะได้
- หลังผู้ใช้เข้าสู่ระบบ ระบบต้องแสดงปุ่ม “Status” ในแถบนำทางหลัก เมื่อเลือกปุ่มนี้ให้เปิดหน้ารายการ Order ของผู้ใช้
- ผู้ใช้สามารถดูสถานะเฉพาะ Order ของตนเอง โดยต้นแบบใช้ Mock account ID ผูกกับ Order ใหม่ และไม่แสดง Order เดิมที่ไม่มีข้อมูลเจ้าของ
- Order ที่ชำระผ่านการจำลองสำเร็จใน development/test ให้ถือเป็น Order ที่ชำระสำเร็จสำหรับต้นแบบและแสดงใน Status; Order ที่ยังรอชำระต้องไม่แสดง
- สถานะ Order ต้องมาจากข้อมูลที่ระบบบันทึกไว้
- ลูกค้าไม่สามารถแก้ไขหรือเปลี่ยนสถานะ Order ได้เอง
- หากไม่สามารถโหลดสถานะล่าสุดได้ ระบบต้องไม่แสดงข้อมูลสถานะที่ไม่ยืนยัน

## Requirements
- FR-19  
  ผู้ใช้สามารถดูรายการ Order ของตนเองได้ โดยหลังเข้าสู่ระบบ ระบบต้องแสดงปุ่ม “Status” ในแถบนำทางหลักเพื่อเปิดหน้ารายการ Order

- FR-20  
  ผู้ใช้สามารถเลือก Order เพื่อดูรายละเอียดและสถานะล่าสุดของ Order ได้

- FR-21  
  ระบบต้องแสดงสถานะของ Order ให้ผู้ใช้ทราบ โดยใช้สถานะพื้นฐาน 4 ขั้นคือ “รอรับ Order” → “กำลังเตรียม” → “พร้อมรับสินค้า” → “รับสินค้าแล้ว”
  เมื่อสถานะเปลี่ยนเป็น “พร้อมรับสินค้า” หรือ “รับสินค้าแล้ว” ระบบต้องแสดงเวลาและสถานะที่เปลี่ยนล่าสุด

- FR-22  
  ระบบต้องแสดงสถานะล่าสุดของ Order ที่ผู้ใช้เลือก และแสดงข้อมูลรายการสั่งซื้อที่เกี่ยวข้อง ได้แก่ รายการสินค้า จำนวน ราคา และสถานะล่าสุด

- FR-23  
  หากผู้ใช้มีหลาย Order ระบบต้องแสดงรายการ Order ให้ผู้ใช้สามารถเลือก Order ที่ต้องการติดตามได้
  รายการ Order ต้องเรียงตามวันที่สร้างล่าสุดก่อน

### Alternative Flow Requirement

- FR-23 / UC-05 Alternative Flow 2a  
  หากลูกค้ามีหลาย Order ระบบต้องแสดงรายการ Order ให้เลือก และผู้ใช้สามารถเลือก Order ที่ต้องการดูสถานะได้

### Exception Flow Requirement

- UC-05 Exception Flow 4a  
  หากระบบไม่สามารถโหลดสถานะล่าสุดของ Order ได้ ระบบต้องแสดงข้อความ “ไม่สามารถโหลดสถานะได้” และมีปุ่ม “ลองใหม่” เพื่อเรียกข้อมูลอีกครั้ง
  โดยไม่แสดงสถานะเดิมที่ยังไม่ได้รับการยืนยันจากระบบ

## Quality Requirements
- NFR-22  
  หน้ารายการเมนูและหน้าตรวจสอบสถานะ Order ต้องตอบสนองภายใน 2 วินาที (p95) ภายใต้จำนวนผู้ใช้พร้อมกัน 100 concurrent users

- NFR-REL-03  
  ระบบต้องแสดงสถานะ Order จากข้อมูลล่าสุดที่ระบบยืนยันแล้ว และต้องไม่แสดงสถานะที่ไม่ถูกบันทึกหรือไม่ผ่านการยืนยันจากระบบ

- NFR-SEC-02  
  ผู้ใช้ต้องสามารถเข้าถึงข้อมูลสถานะและรายละเอียดเฉพาะ Order ของตนเองเท่านั้น

## Acceptance Criteria

- [ ] AC-STATUS-01 (FR-19)

  Given ลูกค้ามี Order อยู่ในระบบและเข้าสู่ระบบแล้ว
  When ลูกค้าเลือกปุ่ม “Status” ในแถบนำทางหลัก
  Then ระบบแสดงรายการ Order ของลูกค้า

- [ ] AC-STATUS-02 (FR-20)

  Given ลูกค้ามี Order อยู่ในระบบ  
  When ลูกค้าเลือก Order ที่ต้องการติดตาม  
  Then ระบบแสดงรายละเอียดและสถานะล่าสุดของ Order นั้น

- [ ] AC-STATUS-03 (FR-21)

  Given Order มีสถานะที่ถูกบันทึกในระบบ  
  When ลูกค้าเปิดรายละเอียด Order  
  Then ระบบแสดงสถานะปัจจุบันของ Order ให้ลูกค้าทราบตามลำดับ 4 ขั้นคือ รอรับ Order → กำลังเตรียม → พร้อมรับสินค้า → รับสินค้าแล้ว
  And เมื่อสถานะเปลี่ยนเป็นพร้อมรับสินค้า หรือ รับสินค้าแล้ว ระบบแสดงเวลาและสถานะที่เปลี่ยนล่าสุด

- [ ] AC-STATUS-04 (FR-22)

  Given ลูกค้าเลือก Order ที่ต้องการติดตาม  
  When ระบบโหลดข้อมูล Order สำเร็จ  
  Then ระบบแสดงสถานะล่าสุดและข้อมูลรายการสั่งซื้อที่เกี่ยวข้องอย่างถูกต้อง ได้แก่ รายการสินค้า จำนวน ราคา และสถานะล่าสุด

- [ ] AC-STATUS-05 (FR-23)

  Given ลูกค้ามีหลาย Order อยู่ในระบบ  
  When ลูกค้าเปิดหน้าติดตามสถานะ Order  
  Then ระบบแสดงรายการ Order ให้ลูกค้าเลือก Order ที่ต้องการติดตาม
  And รายการ Order เรียงตามวันที่สร้างล่าสุดก่อน

- [ ] AC-STATUS-06 (UC-05 Alternative Flow 2a)

  Given ลูกค้ามีหลาย Order  
  When ลูกค้าเลือก Order จากรายการ  
  Then ระบบแสดงรายละเอียดและสถานะของ Order ที่เลือก

- [ ] AC-STATUS-07 (UC-05 Exception Flow 4a)

  Given ลูกค้าเปิดรายละเอียด Order  
  When ระบบไม่สามารถโหลดสถานะล่าสุดได้  
  Then ระบบแสดงข้อความ “ไม่สามารถโหลดสถานะได้” และมีปุ่ม “ลองใหม่” เพื่อเรียกข้อมูลอีกครั้ง
  And ระบบไม่แสดงสถานะเดิมที่ยังไม่ได้รับการยืนยันจากระบบ

- [ ] AC-STATUS-08 (NFR-REL-03)

  Given ระบบมีสถานะ Order ที่ได้รับการยืนยันแล้ว  
  When ลูกค้าเปิดรายละเอียด Order  
  Then ระบบแสดงสถานะล่าสุดที่ถูกบันทึกและยืนยันในระบบ

- [ ] AC-STATUS-09 (NFR-SEC-02)

  Given ลูกค้ามี Order ของตนเองและมี Order ของลูกค้ารายอื่นในระบบ  
  When ลูกค้าเปิดหน้ารายการ Order  
  Then ระบบแสดงเฉพาะ Order ที่ลูกค้ามีสิทธิ์เข้าถึง

## Assumptions and Open Questions

### Assumptions
- ASM-01  
  ผู้ใช้มี Order ที่สร้างและบันทึกอยู่ในระบบแล้ว

- ASM-02  
  ระบบมีสถานะ Order ที่กำหนดไว้เป็นลำดับขั้นตอน 4 ขั้นคือ “รอรับ Order” → “กำลังเตรียม” → “พร้อมรับสินค้า” → “รับสินค้าแล้ว”

- ASM-03  
  ลูกค้าสามารถดูสถานะของ Order ของตนเองได้เท่านั้น

- ASM-04  
  สถานะ Order ถูกเปลี่ยนโดยระบบหรือพนักงานที่มีสิทธิ์ ไม่ใช่โดยลูกค้า

- ASM-05  
  หากไม่สามารถโหลดข้อมูลสถานะได้ ระบบจะแสดงข้อความ “ไม่สามารถโหลดสถานะได้” พร้อมปุ่ม “ลองใหม่” และไม่แสดงสถานะเดิมที่ยังไม่ได้รับการยืนยันจากระบบ

- ASM-06  
  ลูกค้าสามารถมี Order หลายรายการในระบบ และสามารถเลือกดูแต่ละ Order ได้

- ASM-07  
  รายการ Order ในหน้าติดตามควรเรียงตามวันที่สร้างล่าสุดก่อน

- ASM-08  
  Order ที่ timeout หรือยกเลิกยังคงแสดงในรายการ แต่ต้องแสดงสถานะว่า timeout หรือยกเลิก

- ASM-09  
  เมื่อ Order เปลี่ยนเป็น “พร้อมรับสินค้า” หรือ “รับสินค้าแล้ว” ระบบต้องแสดงเวลาและสถานะที่เปลี่ยนล่าสุด

- ASM-10  
  ข้อมูลที่แสดงในรายละเอียด Order ประกอบด้วย รายการสินค้า จำนวน ราคา และสถานะล่าสุด เท่านั้น

- ASM-11  
  สถานะ Order อัปเดตแบบ real-time โดยระบบที่มีข้อมูลล่าสุดและได้รับการยืนยันแล้ว

- ASM-12  
  การเปลี่ยนสถานะเป็น “พร้อมรับสินค้า” และ “รับสินค้าแล้ว” จะถูกดำเนินการโดยพนักงานหลังจากลูกค้าได้รับสินค้าแล้ว

- ASM-13
  ปุ่ม “Status” อยู่ในแถบนำทางหลัก แสดงหลังผู้ใช้เข้าสู่ระบบ และนำไปยังหน้ารายการ Order ก่อนเลือก Order เพื่อเปิดดูรายละเอียดและสถานะ
