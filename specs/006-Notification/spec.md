# Feature: รับแจ้งเตือนเครื่องดื่มพร้อมรับ (Order Ready Notification)
Spec ID: SPEC-NOTIFICATION-001 | Source: SRS v0.1 ข้อ 3.6 (FR-NOTIFICATION) | Use case: UC-06
Owner: <ทีม/คน> | Status: Draft v2 | Updated: 2569-10-26
Depends on: SPEC-ACCOUNT-001, SPEC-ORDER-STATUS-001 | Reviewed by: -

## Goal
นักศึกษา / ลูกค้าได้รับแจ้งเตือนผ่าน LINE เมื่อ Order เปลี่ยนสถานะเป็น “พร้อมรับสินค้า”
เพื่อให้ลูกค้าทราบว่าเครื่องดื่มพร้อมรับโดยไม่ต้องตรวจสอบสถานะผ่านหน้าเว็บซ้ำ ๆ

## Scope

### In scope
- ตรวจสอบ Order ที่เปลี่ยนสถานะเป็น “พร้อมรับสินค้า”
- ตรวจสอบข้อมูล LINE User ID ของลูกค้า
- ส่งข้อความแจ้งเตือนไปยัง LINE Notification Service
- บันทึกผลการส่งแจ้งเตือน
- ป้องกันการส่งแจ้งเตือนซ้ำสำหรับ Order เดิม
- รองรับกรณีที่ลูกค้ายังไม่ได้เชื่อมต่อ LINE

### Out of scope
- การสมัครสมาชิกและเข้าสู่ระบบ
- การเชื่อมต่อบัญชี LINE (อยู่ใน UC-02)
- การอัปเดตสถานะ Order (อยู่ใน UC-08)
- การจัดการ LINE Notification Service
- การส่งข่าวสารหรือโปรโมชั่นทั่วไปผ่าน LINE

## Constraints
- Order ต้องมีสถานะ “พร้อมรับสินค้า” ก่อนเริ่มการแจ้งเตือน
- ลูกค้าต้องเชื่อมต่อบัญชีกับ LINE และมี LINE User ID หากต้องการรับแจ้งเตือน
- ระบบต้องส่งแจ้งเตือนเพียงครั้งเดียวต่อ Order ที่มีสถานะ “พร้อมรับสินค้า” เมื่อส่งสำเร็จแล้ว
- หาก LINE User ID ว่างหรือไม่ถูกต้อง ระบบจะไม่ส่งแจ้งเตือนย้อนหลังอัตโนมัติ แม้ลูกค้าจะเชื่อมต่อ LINE ภายหลัง และสถานะ Order ยังคงเป็น “พร้อมรับสินค้า”
- หาก LINE Notification Service ไม่สามารถส่งข้อความได้ ต้องไม่เปลี่ยนสถานะ Order
- การส่งซ้ำอนุญาตเฉพาะกรณีส่งไม่สำเร็จเท่านั้น ไม่ใช่กรณีส่งสำเร็จแล้ว
- ระบบต้องบันทึกผลการส่งแจ้งเตือนใน Log หรือฐานข้อมูล เพื่อให้ผู้ดูแลระบบตรวจสอบได้

## Requirements
- FR-19
  ระบบต้องตรวจพบและดำเนินการแจ้งเตือนเมื่อ Order เปลี่ยนสถานะเป็น “พร้อมรับสินค้า”

- FR-20
  ระบบต้องตรวจสอบว่า Order มี LINE User ID ของลูกค้าที่เชื่อมต่อไว้ก่อนส่งการแจ้งเตือน
  หาก LINE User ID ว่างหรือไม่ถูกต้อง ให้ถือว่าเป็นกรณี “ยังไม่ได้เชื่อมต่อ LINE” และไม่ส่งข้อความ

- FR-21
  ระบบต้องส่งข้อความแจ้งเตือนผ่าน LINE Notification Service เมื่อพบ LINE User ID ที่ถูกต้อง
  ข้อความแจ้งเตือนต้องมีข้อมูลสั้น ๆ เพียงพอ เช่น หมายเลข Order และข้อความว่า “Order พร้อมรับสินค้า”
  รูปแบบข้อความที่ใช้เป็นข้อความสั้น ๆ เช่น “Order 123 พร้อมรับสินค้า”

- FR-22
  ระบบต้องบันทึกผลการส่งแจ้งเตือนว่า สำเร็จ หรือไม่สำเร็จ ใน Log หรือฐานข้อมูล
  หากส่งไม่สำเร็จ ให้บันทึกว่าไม่สำเร็จ โดยไม่ทำการ retry อัตโนมัติทันที และไม่เปลี่ยนสถานะ Order จาก “พร้อมรับสินค้า”

- FR-23
  ระบบต้องส่งแจ้งเตือนเพียงครั้งเดียวต่อ Order ที่มีสถานะ “พร้อมรับสินค้า”
  หากเคยส่งสำเร็จแล้ว ระบบจะไม่ส่งซ้ำอีกครั้ง

### Alternative Flow Requirement

- FR-20 / UC-06 Alternative Flow 3a
  หากลูกค้ายังไม่ได้เชื่อมต่อ LINE ระบบต้องไม่ส่งข้อความผ่าน LINE และต้องไม่เปลี่ยนสถานะ Order

- FR-23 / UC-06 Alternative Flow 5a
  หากระบบเคยส่งแจ้งเตือน Order เดิมสำเร็จแล้ว ระบบต้องไม่ส่งข้อความซ้ำโดยไม่จำเป็น

### Exception Flow Requirement

- UC-06 Exception Flow 4a
  หาก LINE Notification Service ไม่สามารถตอบกลับหรือส่งข้อความไม่สำเร็จ ระบบต้องบันทึกผลการส่งเป็นไม่สำเร็จ และไม่ทำการ retry อัตโนมัติทันที โดยไม่เปลี่ยนสถานะ Order จาก “พร้อมรับสินค้า”

## Quality Requirements
- NFR-REL-01
  การส่งแจ้งเตือนผ่าน LINE ล้มเหลวต้องไม่ทำให้สถานะ Order ผิดพลาดหรือย้อนกลับจาก “พร้อมรับสินค้า”

- NFR-REL-02
  ระบบต้องสามารถตรวจสอบผลการส่งแจ้งเตือนและป้องกันการส่งข้อความซ้ำสำหรับ Order เดิม

## Acceptance Criteria

- [ ] AC-NOTIFICATION-01 (FR-19 / FR-20 / FR-21)

  Given Order เปลี่ยนสถานะเป็น “พร้อมรับสินค้า” และลูกค้ามี LINE User ID
  When ระบบดำเนินการแจ้งเตือน
  Then ระบบส่งข้อความผ่าน LINE Notification Service และลูกค้าได้รับข้อความแจ้งเตือนพร้อมหมายเลข Order

- [ ] AC-NOTIFICATION-02 (FR-20)

  Given Order เปลี่ยนสถานะเป็น “พร้อมรับสินค้า” แต่ลูกค้ายังไม่ได้เชื่อมต่อ LINE
  When ระบบตรวจสอบข้อมูล LINE
  Then ระบบไม่ส่งข้อความผ่าน LINE และสถานะ Order ยังคงเป็น “พร้อมรับสินค้า”

- [ ] AC-NOTIFICATION-03 (FR-22 / UC-06 Exception Flow 4a)

  Given ระบบส่งข้อความผ่าน LINE Notification Service
  When LINE ไม่สามารถส่งข้อความได้
  Then ระบบบันทึกผลการส่งไม่สำเร็จ และสถานะ Order ยังคงเป็น “พร้อมรับสินค้า”

- [ ] AC-NOTIFICATION-04 (FR-23)

  Given Order เดิมเคยส่งแจ้งเตือนสำเร็จแล้ว
  When ระบบตรวจพบเหตุการณ์แจ้งเตือนซ้ำ
  Then ระบบไม่ส่งข้อความแจ้งเตือนซ้ำ

## Assumptions and Open Questions

### Assumptions
- ลูกค้าสามารถเลือกเชื่อมต่อ LINE จาก UC-02 ได้
- LINE User ID ถูกบันทึกและสัมพันธ์กับบัญชีลูกค้า
- UC-08 เป็นผู้ทำให้ Order เปลี่ยนสถานะเป็น “พร้อมรับสินค้า”
- UC-06 รับผิดชอบเฉพาะการแจ้งเตือนเมื่อ Order พร้อมรับสินค้า
- ข้อความแจ้งเตือนที่ใช้เป็นข้อความสั้น ๆ เช่น “Order 123 พร้อมรับสินค้า”
- หาก LINE User ID ว่างหรือไม่ถูกต้อง ระบบจะไม่ส่งแจ้งเตือนย้อนหลังอัตโนมัติ แม้ลูกค้าจะเชื่อมต่อ LINE ภายหลัง และสถานะ Order ยังคงเป็น “พร้อมรับสินค้า”
- การส่งซ้ำอนุญาตเฉพาะกรณีส่งไม่สำเร็จเท่านั้น ไม่ใช่กรณีส่งสำเร็จแล้ว
- ใช้ `order_id` เป็น key ป้องกันการส่งซ้ำเมื่อส่งสำเร็จแล้ว
- การแจ้งเตือนจะส่งเพียงครั้งเดียวต่อ Order ที่มีสถานะพร้อมรับสินค้า
- หากส่งแจ้งเตือนไม่สำเร็จ ระบบจะบันทึกผลการส่งว่าล้มเหลว โดยไม่ retry อัตโนมัติทันที และไม่เปลี่ยนสถานะ Order

### Open Questions
