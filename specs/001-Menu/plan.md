# แผนงานสำหรับ Feature: ดูเมนูและโปรโมชั่น (Menu & Promotion)

## 1. สรุปแนวทาง
- หน้าเมนูให้ผู้ใช้ทั่วไปดูรายการเครื่องดื่มที่เปิดให้แสดง รวมถึงรายการหมดสต็อก ชื่อ ราคา รายละเอียด สถานะ โปรโมชั่น และค้นหาจากชื่อ ตาม FR-01, FR-02, FR-03, FR-05 และ AC-MENU-01 ถึง AC-MENU-05
- ผู้ใช้ที่เข้าสู่ระบบแล้วเลือกเมนูเพื่อเข้าสู่ขั้นตอน UC-03 โดยยังไม่สร้าง Order; ผู้ใช้ที่ยังไม่เข้าสู่ระบบต้องไป UC-02 และเมื่อเข้าสู่ระบบสำเร็จให้เพิ่มเมนูที่เลือกไว้เข้า Order และไป UC-03 ตาม FR-02, Alternative Flow Requirement, AC-MENU-02, AC-MENU-08 และ ASM-02
- เมื่อเข้าสู่ระบบไม่สำเร็จหรือยกเลิก ต้องยกเลิกเฉพาะเมนูที่เลือกก่อนเข้าสู่ระบบโดยไม่กระทบ Order อื่น ตาม FR-02, Exception Flow Requirement และ AC-MENU-09
- การจัดเก็บและส่งต่อเมนูที่เลือก รวมถึงการจัดการเมื่อราคา โปรโมชั่น หรือสต็อกเปลี่ยนระหว่างเลือกกับยืนยัน Order ยังเป็น Open Questions; แผนนี้จึงระบุพฤติกรรมที่ต้องรองรับ แต่ไม่กำหนดกลไกหรือกติกาแทนทีม
- ขอบเขตนี้ไม่รวมการสร้างระบบสมัครสมาชิก/เข้าสู่ระบบของ UC-02, การกำหนดจำนวนหรือตัวเลือกเครื่องดื่ม, การแก้ไขหรือลบรายการ Order, การยืนยันหรือสร้าง Order, การชำระเงิน, และฟังก์ชันอื่นใน Out of scope; แผนรองรับเฉพาะการส่งต่อเมนูเข้าสู่ขั้นตอนของ UC-03 ตามที่ spec ระบุ

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) สำหรับหน้าเมนูและโปรโมชั่น | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้แสดงรายการเมนู, search, status badge, และ section โปรโมชั่นในหน้าเดียวกัน |
| Python FastAPI สำหรับ API ดึงข้อมูลเมนูและโปรโมชั่น | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้คืนข้อมูลเมนูที่เปิดขายพร้อมโปรโมชั่นที่กำลังใช้งานอยู่ |
| ฐานข้อมูลเชิงสัมพันธ์ (เช่น PostgreSQL) | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้เก็บเมนู, สถานะสินค้า, และข้อมูลโปรโมชั่นที่ใช้งานอยู่ |
| Search service สำหรับ partial match ไม่แยกตัวพิมพ์เล็ก/ใหญ่ | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สำหรับ FR-03 และ ASM-01 |
| Error state UI สำหรับ “ไม่สามารถโหลดข้อมูลได้” | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้แสดงข้อความและปุ่ม “ลองใหม่” ตาม UC-01 Exception Flow 2a |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ FR / NFR |
|---|---|---|
| MenuItem | `menu_id`, `name`, `price`, `description`, `status`, `is_active`, `updated_at` | รองรับ FR-01, FR-02, FR-03, AC-MENU-01, AC-MENU-02, AC-MENU-03 |
| Promotion | `promotion_id`, `title`, `status`, `start_at`, `end_at`, `priority` | รองรับ FR-05, AC-MENU-04 |
| MenuPromotionLink | `menu_id`, `promotion_id`, `display_order` | รองรับ FR-05, ASM-03, AC-MENU-04 |
| MenuResponse | รายการเมนูและโปรโมชั่นที่กำลังใช้งาน รวมถึงราคาหลังหักโปรโมชั่นสำหรับการแสดงและส่งต่อ | รองรับ FR-01, FR-02, FR-05, AC-MENU-01, AC-MENU-02, AC-MENU-04 |
| SearchRequest | `keyword` | รองรับ FR-03, AC-MENU-03 |
| MenuLoadResult | `items[]`, `promotion[]`, `status`, `error_message`, `retry_action` | รองรับ UC-01 Exception Flow 2a, AC-MENU-05 |

หมายเหตุโมเดลข้อมูล:
- ไม่สร้างข้อมูลบัญชีผู้ใช้หรือโมเดล Order/Payment; การเข้าสู่ระบบและการจัดการ Order เป็นหน้าที่ของ UC-02/UC-03
- `MenuItem.status` ต้องรองรับการแสดงสถานะเมนูที่หมดสต็อกและปิดการใช้งานปุ่ม “สั่งซื้อ” ตาม FR-02
- `Promotion.status` ต้องคัดเฉพาะโปรโมชั่นที่กำลังใช้งานอยู่ และใช้ลำดับแสดงเมนูที่มีโปรโมชั่นไว้ด้านบนตาม FR-05
- response สำหรับส่งต่อไป UC-03 ต้องมีราคาหลังหักโปรโมชั่นที่คำนวณจาก UC-01; UC-03 ต้องไม่คำนวณส่วนลดซ้ำตาม FR-05 และ ASM-07
- รูปแบบจัดเก็บ/ส่งต่อรายการที่เลือกและกติกาเมื่อราคา โปรโมชั่น หรือสต็อกเปลี่ยนยังไม่กำหนดจนกว่าทีมตอบ Open Questions; ห้ามเลือกวิธีหรือกติกาแทนทีม

## 4. API / หน้าจอ

- `GET /api/menu` — Input: ไม่มี; Output: รายการเมนูที่เปิดให้แสดง ทั้งที่เปิดขายและหมดสต็อก พร้อมชื่อ ราคา รายละเอียด สถานะ และข้อมูลโปรโมชั่นที่เกี่ยวข้อง — รองรับ FR-01, FR-02, FR-05, AC-MENU-01, AC-MENU-02, AC-MENU-04
- `GET /api/promotions/active` — Input: ไม่มี; Output: เฉพาะโปรโมชั่นที่กำลังใช้งานอยู่ — รองรับ FR-05, AC-MENU-04
- `GET /menu` — หน้าเมนูและโปรโมชั่นในหน้าเดียว รองรับรายการว่าง สถานะโหลดผิดพลาด และปุ่มลองใหม่ — รองรับ FR-01, FR-05, AC-MENU-01, AC-MENU-04, AC-MENU-05
- `POST /api/menu/search` — Input: keyword; Output: รายการที่ตรงกับชื่อแบบ partial match โดยไม่แยกตัวพิมพ์เล็ก/ใหญ่ และแสดง “ไม่พบเมนู” เมื่อไม่พบผลลัพธ์ — รองรับ FR-03, AC-MENU-03
- การส่งเมนูที่เลือกไปยัง UC-02/UC-03 — ต้องรองรับการนำผู้ใช้ที่ยังไม่เข้าสู่ระบบไป UC-02, การเพิ่มรายการที่เลือกไว้เข้า Order หลังเข้าสู่ระบบสำเร็จและส่งต่อไป UC-03, การยกเลิกรายการที่เลือกเมื่อเข้าสู่ระบบไม่สำเร็จ/ยกเลิก และการกลับมาเลือกเมนูเพิ่มโดยคง Order เดิม ตาม FR-02, Alternative Flow Requirement, Exception Flow Requirement, ASM-02, ASM-08, AC-MENU-02, AC-MENU-08 และ AC-MENU-09; รูปแบบ API/state transport รอคำตอบ Open Question
- การส่งข้อมูลเมนูโปรโมชั่นไป UC-03 ต้องส่งราคาหลังหักโปรโมชั่นที่คำนวณใน UC-01 โดยไม่คำนวณส่วนลดซ้ำ ตาม FR-05, ASM-07 และ AC-MENU-04; รายละเอียดการรับมือเมื่อข้อมูลเปลี่ยนระหว่างทางรอคำตอบ Open Question
- เมื่อ API โหลดเมนูหรือโปรโมชั่นไม่สำเร็จ UI แสดงข้อความแจ้งว่าไม่สามารถโหลดข้อมูลได้และปุ่ม “ลองใหม่”; การลองใหม่ต้องโหลดทั้งเมนูและโปรโมชั่น — รองรับ Exception Flow Requirement, ASM-05 และ AC-MENU-05

## 5. ตารางตรวจ Constraints

| ข้อกำหนดใน Constraints ของ spec (ไม่มี Constraint ID ระบุไว้) | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ผู้ใช้ทั่วไปสามารถดูข้อมูลเมนูและโปรโมชั่นได้โดยไม่ต้องเข้าสู่ระบบ | API อ่านข้อมูลและหน้าเมนูไม่บังคับการเข้าสู่ระบบสำหรับการดู | ใช้แล้ว |
| ผู้ใช้ต้องเข้าสู่ระบบก่อนเพิ่มเครื่องดื่มเข้า Order | ตรวจ session/สถานะผู้ใช้ที่จุดเริ่มส่งต่อ; การยืนยันตัวตนเป็นหน้าที่ UC-02 | ใช้แล้ว; กลไกส่งต่อรอ Open Question |
| หากผู้ใช้ยังไม่ได้เข้าสู่ระบบ ระบบต้องนำผู้ใช้ไปยัง UC-02 ก่อนเพิ่มเครื่องดื่มเข้า Order | เส้นทางจากปุ่ม “สั่งซื้อ” ไป UC-02 | ใช้แล้ว; กลไกส่งต่อรอ Open Question |
| ระบบต้องเก็บเมนูที่เลือกไว้ระหว่างเข้าสู่ระบบ และเพิ่มเมนูเข้า Order อัตโนมัติเมื่อเข้าสู่ระบบสำเร็จ | flow เชื่อม UC-01, UC-02 และ UC-03; ไม่สร้างระบบ Login หรือสร้าง Order ใน UC-01 | ใช้แล้ว; วิธีจัดเก็บ/ส่งต่อรอ Open Question |
| หากเข้าสู่ระบบไม่สำเร็จหรือผู้ใช้ยกเลิกขั้นตอนเข้าสู่ระบบ ระบบต้องยกเลิกรายการที่เลือกไว้ก่อนเข้าสู่ระบบ โดยไม่กระทบ Order อื่นที่มีอยู่ | ยกเลิกเฉพาะรายการที่เลือกค้างไว้ ไม่แก้ไข Order อื่น | ใช้แล้ว; กลไกส่งต่อรอ Open Question |
| การค้นหาเมนูต้องค้นหาจากชื่อเมนูแบบ partial match และไม่แยกตัวพิมพ์เล็ก/ใหญ่ | `POST /api/menu/search` | ใช้แล้ว |
| เมนูที่หมดสต็อกต้องแสดงสถานะ “หมด” และไม่สามารถกดสั่งซื้อได้ | `MenuItem.status` และ UI ปิดปุ่ม “สั่งซื้อ” | ใช้แล้ว |
| ระบบต้องแสดงเฉพาะโปรโมชั่นที่กำลังใช้งานอยู่ | `GET /api/promotions/active` และ section โปรโมชั่น | ใช้แล้ว |
| เมนูที่มีโปรโมชั่นต้องแสดงอยู่ด้านบนสุดของรายการเมนู | การเรียงลำดับรายการในผลลัพธ์ที่แสดง | ใช้แล้ว |
| ราคาที่ส่งต่อไปยัง UC-03 ต้องเป็นราคาหลังหักโปรโมชั่นตามที่ระบบคำนวณไว้ โดย UC-03 ไม่คำนวณส่วนลดซ้ำ | ส่งราคาหลังหักโปรโมชั่นจาก UC-01 ไป UC-03 | ใช้แล้ว; กติกาเมื่อข้อมูลเปลี่ยนรอ Open Question |
| การเลือกเมนูจากหน้า UC-01 ยังไม่ถือว่าเป็นการสร้าง Order | UC-01 ส่งรายการเข้าสู่ขั้นตอนของ UC-03 เท่านั้น ไม่ยืนยันหรือสร้าง Order | ใช้แล้ว |
| การโหลดข้อมูลใหม่ต้องโหลดทั้งข้อมูลเมนูและโปรโมชั่น | ปุ่ม “ลองใหม่” เรียกโหลดข้อมูลทั้งสองชุดใหม่ | ใช้แล้ว |

## 7. ลำดับงาน

1. วาง data model และ read API สำหรับรายการเมนูและโปรโมชั่น โดยแสดงรายการที่เปิดให้แสดง ทั้งเมนูเปิดขายและหมดสต็อก ตาม FR-01, FR-02, FR-05 และ AC-MENU-01
2. ทำหน้าเมนูให้โหลดและแสดงรายการ/สถานะว่าง พร้อมการค้นหา partial match แบบไม่แยกตัวพิมพ์เล็ก/ใหญ่ ตาม FR-01, FR-03, AC-MENU-01 และ AC-MENU-03
3. ทำการแสดงโปรโมชั่น ราคาโปรโมชั่น และลำดับรายการ; ทดสอบทั้งมีและไม่มีโปรโมชั่น และส่งราคาหลังหักโปรโมชั่นไป UC-03 ตาม FR-05, ASM-03, ASM-04, ASM-07 และ AC-MENU-04
4. ทำเส้นทางเลือกเมนูสำหรับผู้ใช้ที่เข้าสู่ระบบแล้วไปยัง UC-03 โดยไม่สร้าง Order และสำหรับผู้ใช้ที่ยังไม่เข้าสู่ระบบไป UC-02; รองรับการกลับมาเลือกเพิ่มโดยคง Order เดิม ตาม FR-02, Alternative Flow Requirement, ASM-06, ASM-08 และ AC-MENU-02 การเชื่อมต่อที่ขึ้นกับวิธีจัดเก็บ/ส่งต่อรายการรอคำตอบ Open Question
5. ทำการเพิ่มเมนูที่เลือกไว้เข้า Order หลังเข้าสู่ระบบสำเร็จ และยกเลิกเฉพาะรายการที่ค้างเมื่อเข้าสู่ระบบไม่สำเร็จหรือยกเลิก โดยไม่กระทบ Order อื่น ตาม FR-02, Alternative Flow Requirement, Exception Flow Requirement, ASM-02, AC-MENU-02, AC-MENU-08 และ AC-MENU-09; ไม่สร้างระบบ Login หรือระบบ Order ในฟีเจอร์นี้
6. ทำสถานะโหลดผิดพลาดและการลองใหม่ให้โหลดทั้งเมนูและโปรโมชั่น ตาม Exception Flow Requirement, ASM-05 และ AC-MENU-05
7. วัดประสิทธิภาพตามเงื่อนไขผู้ใช้พร้อมกัน 100 คน และทดสอบภารกิจค้นหากับผู้ใช้ใหม่ 10 คน ตาม NFR-22, NFR-26, AC-MENU-06 และ AC-MENU-07

## 8. สิ่งที่ยังไม่ทำ

- **วิธีจัดเก็บและส่งต่อเมนูที่เลือกไว้ระหว่าง UC-01 และ UC-02/UC-03 ในระดับการออกแบบระบบ:** ยังไม่กำหนดกลไก, API contract หรือรูปแบบ state; ส่วน handoff ที่ต้องอาศัยการตัดสินใจนี้ยังสรุปเพื่อนำไป implement ไม่ได้จนกว่าทีมตอบ
- **วิธีจัดการกรณีราคา โปรโมชั่น หรือสถานะสต็อกเปลี่ยนแปลงระหว่างที่ผู้ใช้เลือกเมนูกับการยืนยันคำสั่งซื้อ:** ยังไม่กำหนดกติกาหรือผลที่ผู้ใช้ต้องเห็น; ห้ามเดาพฤติกรรม และต้องปรับรายละเอียดการเชื่อมต่อ/ทดสอบหลังทีมตอบ
- Open Questions ข้างต้นยังไม่มี Q-ID ใน spec; แผนนี้จึงอ้างด้วยข้อความตาม spec โดยไม่สร้าง ID ใหม่
