# UC-01 — Feature: ดูเมนูและโปรโมชั่น (Menu & Promotion)

Spec ID: SPEC-MENU-001 | Source: SRS v0.1 ข้อ 3.1 (FR-MENU) | Use case: UC-01  
Owner: \<ทีม/คน> | Status: Draft v2 | Updated: 2569-10-26  
Depends on: SPEC-ACCOUNT-001, SPEC-ORDER-001 | Reviewed by: -

## Goal

นักศึกษา / ลูกค้า (ผู้ใช้ทั่วไปของระบบเมนูและโปรโมชั่นเดียวกัน) สามารถดูรายการเครื่องดื่ม ราคา รายละเอียด สถานะสินค้า และโปรโมชั่นของร้าน OWL CHA รวมถึงค้นหาเครื่องดื่มจากชื่อเมนู เพื่อใช้ข้อมูลประกอบการตัดสินใจก่อนสั่งซื้อ และสามารถเลือกเครื่องดื่มเพื่อเข้าสู่ขั้นตอนการสั่งซื้อได้ โดยต้องเข้าสู่ระบบก่อนเพิ่มเครื่องดื่มลงในรายการสั่งซื้อชั่วคราว

## Scope

### In scope

- ดูรายการเครื่องดื่มที่ร้านเปิดขายและรายการที่หมดสต็อก
- ดูชื่อ ราคา รายละเอียด และสถานะของเครื่องดื่มแต่ละรายการ
- ค้นหาเครื่องดื่มจากชื่อเมนู
- ดูโปรโมชั่นที่กำลังใช้งานอยู่
- แสดงราคาหลังหักโปรโมชั่นสำหรับเมนูที่มีโปรโมชั่น
- เริ่มต้นขั้นตอนสั่งซื้อโดยเลือกเครื่องดื่มจากหน้าเมนู
- นำผู้ใช้ที่ยังไม่ได้เข้าสู่ระบบไปยัง UC-02 เพื่อเข้าสู่ระบบหรือสมัครสมาชิกก่อนเพิ่มเครื่องดื่มลงในรายการสั่งซื้อชั่วคราว
- เก็บเมนูที่ผู้ใช้เลือกไว้ระหว่างเข้าสู่ระบบ และเพิ่มเมนูลงในรายการสั่งซื้อชั่วคราวเมื่อเข้าสู่ระบบสำเร็จ
- ยกเลิกเฉพาะเมนูที่เลือกไว้ก่อนเข้าสู่ระบบ หากเข้าสู่ระบบไม่สำเร็จหรือผู้ใช้ยกเลิกขั้นตอน โดยไม่กระทบรายการเดิม
- ส่งรายการสั่งซื้อชั่วคราวไปยัง UC-03 เพื่อดำเนินการสั่งซื้อ; การสร้าง Order ที่สมบูรณ์เป็นไปตาม UC-03
- โหลดข้อมูลเมนูและโปรโมชั่นใหม่เมื่อผู้ใช้กดปุ่ม “ลองใหม่”

### Out of scope

- การกรองเครื่องดื่มตามประเภท (FR-04)
- การสมัครสมาชิกและการตรวจสอบข้อมูลเข้าสู่ระบบ ซึ่งเป็นหน้าที่ของ UC-02
- การกำหนดจำนวนและตัวเลือกของเครื่องดื่มใน Order
- การแก้ไขจำนวนหรือลบรายการใน Order
- การยืนยันคำสั่งซื้อและการสร้าง Order
- การชำระเงินออนไลน์
- การตรวจสอบสถานะ Order
- การรับแจ้งเตือนเมื่อเครื่องดื่มพร้อมรับ
- การดูและอัปเดต Order ของพนักงาน
- การจัดการเมนู ราคา โปรโมชั่น และสถานะสินค้า
- การดูรายงานยอดขายและสถิติ

## Constraints

- ผู้ใช้ทั่วไปสามารถดูข้อมูลเมนูและโปรโมชั่นได้โดยไม่ต้องเข้าสู่ระบบ
- ผู้ใช้ต้องเข้าสู่ระบบก่อนเพิ่มเครื่องดื่มลงในรายการสั่งซื้อชั่วคราว
- หากผู้ใช้ยังไม่ได้เข้าสู่ระบบ ระบบต้องนำผู้ใช้ไปยัง UC-02 ก่อนเพิ่มเครื่องดื่มลงในรายการสั่งซื้อชั่วคราว
- ระบบต้องเก็บเมนูที่เลือกไว้ระหว่างเข้าสู่ระบบ และเพิ่มเมนูลงในรายการสั่งซื้อชั่วคราวเมื่อเข้าสู่ระบบสำเร็จ
- หากเข้าสู่ระบบไม่สำเร็จหรือผู้ใช้ยกเลิกขั้นตอนเข้าสู่ระบบ ระบบต้องยกเลิกเฉพาะรายการที่เลือกไว้ก่อนเข้าสู่ระบบ โดยไม่กระทบรายการเดิมในรายการสั่งซื้อชั่วคราว
- การค้นหาเมนูต้องค้นหาจากชื่อเมนูแบบ partial match และไม่แยกตัวพิมพ์เล็ก/ใหญ่
- เมนูที่หมดสต็อกต้องแสดงสถานะ “หมด” และไม่สามารถกดสั่งซื้อได้
- ระบบต้องแสดงเฉพาะโปรโมชั่นที่กำลังใช้งานอยู่
- เมนูที่มีโปรโมชั่นต้องแสดงอยู่ด้านบนสุดของรายการเมนู
- ราคาที่ส่งต่อไปยัง UC-03 ต้องเป็นราคาหลังหักโปรโมชั่นตามที่ระบบคำนวณไว้ โดย UC-03 ไม่คำนวณส่วนลดซ้ำ
- การเลือกเมนูจากหน้า UC-01 ยังไม่ถือว่าเป็นการสร้าง Order
- การโหลดข้อมูลใหม่ต้องโหลดทั้งข้อมูลเมนูและโปรโมชั่น

## Requirements

### FR-01: แสดงรายการเครื่องดื่ม

ระบบต้องแสดงรายการเครื่องดื่มที่เปิดให้แสดงบนหน้าร้าน รวมถึงเมนูที่หมดสต็อก หากระบบไม่มีรายการเครื่องดื่มเลย ระบบต้องแสดงข้อความ “ขณะนี้ไม่มีรายการเครื่องดื่ม”

### FR-02: แสดงรายละเอียดและเริ่มต้นการสั่งซื้อ

ระบบต้องแสดงชื่อ ราคา รายละเอียด และสถานะของเครื่องดื่มแต่ละรายการ

- เมนูที่เปิดขายและมีสต็อกต้องมีปุ่ม “สั่งซื้อ”
- เมื่อผู้ใช้ที่เข้าสู่ระบบแล้วคลิกปุ่ม “สั่งซื้อ” ระบบต้องเพิ่มเมนูที่เลือกลงในรายการสั่งซื้อชั่วคราวและนำผู้ใช้ไปยัง UC-03 โดยยังไม่สร้าง Order ที่สมบูรณ์
- เมื่อผู้ใช้ที่ยังไม่ได้เข้าสู่ระบบคลิกปุ่ม “สั่งซื้อ” ระบบต้องเก็บเมนูที่เลือกไว้และนำผู้ใช้ไปยัง UC-02 เพื่อเข้าสู่ระบบหรือสมัครสมาชิก
- เมื่อเข้าสู่ระบบสำเร็จ ระบบต้องนำเมนูที่เลือกไว้กลับมาเพิ่มลงในรายการสั่งซื้อชั่วคราว และนำผู้ใช้ไปยัง UC-03 เพื่อดำเนินการต่อ
- หากเข้าสู่ระบบไม่สำเร็จหรือผู้ใช้ยกเลิกขั้นตอนเข้าสู่ระบบ ระบบต้องยกเลิกเฉพาะเมนูที่เลือกไว้ก่อนเข้าสู่ระบบ โดยไม่กระทบรายการเดิมในรายการสั่งซื้อชั่วคราว
- การยืนยันรายการสั่งซื้อก่อนชำระเงินยังไม่ถือว่าเป็นการสร้าง Order ที่สมบูรณ์; การสร้าง Order ที่สมบูรณ์เกิดหลังชำระเงินสำเร็จตาม UC-03
- เมนูที่หมดสต็อกต้องแสดงสถานะ “หมด” และปุ่ม “สั่งซื้อ” ต้องไม่สามารถใช้งานได้

### FR-03: ค้นหาเครื่องดื่ม

ผู้ใช้สามารถค้นหาเครื่องดื่มจากชื่อเมนูได้แบบ partial match โดยไม่แยกตัวพิมพ์เล็ก/ใหญ่ เมื่อไม่พบรายการที่ตรงกับคำค้น ระบบต้องแสดงข้อความ “ไม่พบเมนู”

### FR-05: แสดงโปรโมชั่น

ระบบต้องแสดงโปรโมชั่นที่กำลังใช้งานอยู่บนหน้าเมนูเดียวกัน และจัดเรียงเมนูที่มีโปรโมชั่นไว้ด้านบนสุด

สำหรับเมนูที่มีโปรโมชั่น ระบบต้องคำนวณและแสดงราคาหลังหักโปรโมชั่น และส่งราคาดังกล่าวต่อไปยัง UC-03 โดย UC-03 ไม่คำนวณส่วนลดซ้ำ

ก่อนยืนยันคำสั่งซื้อ ต้องตรวจสอบราคา โปรโมชั่น และสถานะสินค้าโดยใช้ข้อมูลล่าสุด หากราคาเปลี่ยน ระบบต้องแสดงราคาใหม่และแจ้งผู้ใช้ก่อนยืนยัน หากโปรโมชั่นเปลี่ยนหรือหมดอายุ ระบบต้องตรวจสอบสิทธิ์และคำนวณราคาตามเงื่อนไขล่าสุด พร้อมแจ้งผู้ใช้เมื่อราคา/ส่วนลดเปลี่ยน หากสถานะสินค้าเปลี่ยนเป็น “หมด” ระบบต้องแจ้งผู้ใช้และไม่อนุญาตให้ยืนยันรายการนั้น เมื่อข้อมูลเปลี่ยน ผู้ใช้ต้องตรวจสอบข้อมูลที่อัปเดตและยืนยันอีกครั้งก่อนดำเนินการต่อ หากข้อมูลไม่เปลี่ยนแปลงจึงดำเนินการต่อด้วยข้อมูลล่าสุด โดยส่วนลดต้องถูกคำนวณเพียงครั้งเดียวและ UC-03 ไม่คำนวณซ้ำ ผู้รับผิดชอบการตรวจสอบ/คำนวณข้อมูลล่าสุดยังเป็น Open Question

หากไม่มีโปรโมชั่นที่กำลังใช้งานอยู่ ระบบต้องไม่แสดงส่วนโปรโมชั่น แต่ยังคงแสดงรายการเครื่องดื่มทั้งเมนูที่เปิดขายและเมนูที่หมดสต็อก โดยเมนูที่หมดสต็อกต้องแสดงสถานะ “หมด” และปุ่ม “สั่งซื้อ” ต้องไม่สามารถใช้งานได้

### Alternative Flow Requirement

- **FR-02 / UC-01 Alternative Flow 2a:** หากผู้ใช้ยังไม่ได้เข้าสู่ระบบและคลิกปุ่ม “สั่งซื้อ” ระบบต้องเก็บเมนูที่เลือกไว้และนำผู้ใช้ไปยัง UC-02
- **FR-02 / UC-01 Alternative Flow 2b:** หากผู้ใช้เข้าสู่ระบบสำเร็จ ระบบต้องเพิ่มเมนูที่เลือกไว้ลงในรายการสั่งซื้อชั่วคราวอัตโนมัติและนำผู้ใช้ไปยัง UC-03
- **FR-02 / UC-01 Alternative Flow 2c:** หากผู้ใช้ต้องการสั่งเครื่องดื่มเพิ่มเติม ระบบต้องให้ผู้ใช้กลับไปยังหน้าเมนูเพื่อเลือกเครื่องดื่มเพิ่มเติม โดยเก็บรายการเดิมในรายการสั่งซื้อชั่วคราวไว้

### Exception Flow Requirement

- **UC-01 Exception Flow 2a:** หากระบบไม่สามารถโหลดข้อมูลเมนูหรือโปรโมชั่นได้ ระบบต้องแสดงข้อความแจ้งว่าไม่สามารถโหลดข้อมูลได้ และมีปุ่ม “ลองใหม่” เพื่อโหลดข้อมูลเมนูและโปรโมชั่นใหม่อีกครั้ง
- **UC-01 Exception Flow 2b:** หากเข้าสู่ระบบไม่สำเร็จหรือผู้ใช้ยกเลิกขั้นตอนเข้าสู่ระบบ ระบบต้องยกเลิกเฉพาะเมนูที่เลือกไว้ก่อนเข้าสู่ระบบ และไม่เพิ่มเมนูดังกล่าวลงในรายการสั่งซื้อชั่วคราว โดยไม่กระทบรายการเดิม

## Quality Requirements

- **NFR-22:** หน้าเมนูต้องตอบสนองภายใน 2 วินาที (p95) ภายใต้จำนวนผู้ใช้พร้อมกัน 100 concurrent users
- **NFR-26:** ผู้ใช้ใหม่อย่างน้อย 8 ใน 10 คน ต้องสามารถค้นหาเมนูบนหน้าเมนูได้โดยไม่ต้องขอความช่วยเหลือ

## Acceptance Criteria

### AC-MENU-01 (FR-01)

Given ร้านมีรายการเครื่องดื่มที่เปิดให้แสดงบนหน้าร้าน  
When ผู้ใช้เปิดหน้ารายการเมนู  
Then ระบบแสดงรายการเครื่องดื่มที่เปิดให้แสดงบนหน้าร้าน

Given ระบบไม่มีรายการเครื่องดื่มเลย  
When ผู้ใช้เปิดหน้ารายการเมนู  
Then ระบบแสดงข้อความ “ขณะนี้ไม่มีรายการเครื่องดื่ม”

### AC-MENU-02 (FR-02)

Given ผู้ใช้เข้าสู่ระบบแล้วและมีเมนูที่เปิดขาย  
When ผู้ใช้คลิกปุ่ม “สั่งซื้อ” ของเมนูนั้น  
Then ระบบเพิ่มเมนูที่เลือกลงในรายการสั่งซื้อชั่วคราวและนำผู้ใช้ไปยัง UC-03 โดยยังไม่สร้าง Order ที่สมบูรณ์

Given ผู้ใช้ยังไม่ได้เข้าสู่ระบบและมีเมนูที่เปิดขาย  
When ผู้ใช้คลิกปุ่ม “สั่งซื้อ”  
Then ระบบเก็บเมนูที่เลือกไว้และนำผู้ใช้ไปยัง UC-02

Given ผู้ใช้เข้าสู่ระบบสำเร็จหลังจากเลือกเมนูจาก UC-01  
When ระบบดำเนินการหลังเข้าสู่ระบบสำเร็จ  
Then ระบบเพิ่มเมนูที่เลือกไว้ลงในรายการสั่งซื้อชั่วคราวอัตโนมัติและนำผู้ใช้ไปยัง UC-03

Given ผู้ใช้เข้าสู่ระบบไม่สำเร็จหรือยกเลิกขั้นตอนเข้าสู่ระบบ  
When ระบบสิ้นสุดขั้นตอนเข้าสู่ระบบ  
Then ระบบยกเลิกเฉพาะเมนูที่เลือกไว้ก่อนเข้าสู่ระบบและไม่กระทบรายการเดิมในรายการสั่งซื้อชั่วคราว

Given ระบบมีเมนูที่หมดสต็อก  
When ผู้ใช้เปิดหน้ารายการเมนู  
Then เมนูแสดงสถานะ “หมด” และปุ่ม “สั่งซื้อ” ไม่สามารถใช้งานได้

### AC-MENU-03 (FR-03)

Given ระบบมีรายการเครื่องดื่มอยู่ในระบบ  
When ผู้ใช้ค้นหาเครื่องดื่มจากชื่อเมนู  
Then ระบบแสดงรายการเครื่องดื่มที่ตรงกับคำค้นแบบ partial match โดยไม่แยกตัวพิมพ์เล็ก/ใหญ่ และหากไม่พบรายการ ระบบแสดงข้อความ “ไม่พบเมนู”

### AC-MENU-04 (FR-05)

Given ระบบมีโปรโมชั่นที่กำลังใช้งานอยู่  
When ผู้ใช้เปิดหน้าเมนู  
Then ระบบแสดงโปรโมชั่นที่กำลังใช้งานอยู่บนหน้าเมนูเดียวกัน แสดงราคาหลังหักโปรโมชั่น และจัดเรียงเมนูที่มีโปรโมชั่นไว้ด้านบนสุด

Given ผู้ใช้เลือกเมนูที่มีโปรโมชั่นเพื่อเข้าสู่ UC-03  
When ระบบส่งข้อมูลเมนูไปยัง UC-03  
Then ระบบส่งราคาหลังหักโปรโมชั่นตามที่คำนวณไว้ โดย UC-03 ไม่คำนวณส่วนลดซ้ำ

Given ราคา โปรโมชั่น หรือสถานะสินค้าที่เลือกเปลี่ยนแปลงก่อนยืนยันคำสั่งซื้อ  
When ระบบตรวจสอบข้อมูลล่าสุด  
Then ระบบแสดงและแจ้งข้อมูลราคาหรือส่วนลดที่เปลี่ยนแปลงให้ผู้ใช้ตรวจสอบและยืนยันอีกครั้ง; หากสถานะสินค้าเป็น “หมด” ระบบแจ้งผู้ใช้และไม่อนุญาตให้ยืนยันรายการนั้น โดยใช้ข้อมูลล่าสุดและไม่คำนวณส่วนลดซ้ำ

Given ไม่มีโปรโมชั่นที่กำลังใช้งานอยู่  
When ผู้ใช้เปิดหน้าเมนู  
Then ระบบไม่แสดงส่วนโปรโมชั่น แต่ยังแสดงเมนูที่เปิดขายและเมนูที่หมดสต็อก โดยเมนูที่หมดสต็อกแสดงสถานะ “หมด” และปุ่ม “สั่งซื้อ” ไม่สามารถใช้งานได้

### AC-MENU-05 (UC-01 Exception Flow 2a)

Given ระบบไม่สามารถโหลดข้อมูลเมนูหรือโปรโมชั่นได้  
When ผู้ใช้เปิดหน้ารายการเมนู  
Then ระบบแสดงข้อความแจ้งว่าไม่สามารถโหลดข้อมูลได้ และมีปุ่ม “ลองใหม่”

Given ผู้ใช้กดปุ่ม “ลองใหม่”  
When ระบบเรียกโหลดข้อมูลอีกครั้ง  
Then ระบบโหลดข้อมูลเมนูและโปรโมชั่นใหม่

### AC-MENU-06 (NFR-22)

Given ระบบอยู่ภายใต้จำนวนผู้ใช้พร้อมกัน 100 concurrent users  
When ผู้ใช้เปิดหน้าเมนู  
Then p95 ของเวลาตอบสนองต้องไม่เกิน 2 วินาที

### AC-MENU-07 (NFR-26)

Given ผู้ใช้ใหม่จำนวน 10 คน  
When ผู้ใช้แต่ละคนได้รับภารกิจ “ค้นหาเครื่องดื่มชื่อ [ชื่อเมนูทดสอบ] จากหน้ารายการเมนู”  
Then ผู้ใช้อย่างน้อย 8 คนต้องป้อนชื่อเมนูในช่องค้นหาและพบรายการที่ตรงกับชื่อที่กำหนดได้ด้วยตนเอง โดยไม่ต้องได้รับความช่วยเหลือจากผู้ทดสอบ

### AC-MENU-08 (UC-01 Alternative Flow 2a / 2b)

Given ผู้ใช้ยังไม่ได้เข้าสู่ระบบและเลือกเมนูที่เปิดขาย  
When ผู้ใช้คลิกปุ่ม “สั่งซื้อ” และเข้าสู่ระบบสำเร็จ  
Then ระบบเพิ่มเมนูที่เลือกไว้ลงในรายการสั่งซื้อชั่วคราวอัตโนมัติและนำผู้ใช้ไปยัง UC-03 โดยยังไม่สร้าง Order ที่สมบูรณ์

### AC-MENU-09 (UC-01 Exception Flow 2b)

Given ผู้ใช้เลือกเมนูไว้ก่อนเข้าสู่ระบบ  
When ผู้ใช้เข้าสู่ระบบไม่สำเร็จหรือยกเลิกขั้นตอนเข้าสู่ระบบ  
Then ระบบยกเลิกเมนูที่เลือกไว้ก่อนเข้าสู่ระบบ และไม่กระทบรายการเดิมในรายการสั่งซื้อชั่วคราว

## Assumptions and Open Questions

### Assumptions

- **ASM-01:** การค้นหาเมนูทำแบบ partial match โดยไม่แยกตัวพิมพ์เล็ก/ใหญ่
- **ASM-02:** ผู้ใช้ต้องเข้าสู่ระบบก่อนเพิ่มเครื่องดื่มลงในรายการสั่งซื้อชั่วคราว หากยังไม่ได้เข้าสู่ระบบ ระบบจะเก็บเมนูที่เลือกไว้และนำผู้ใช้ไปยัง UC-02 เมื่อเข้าสู่ระบบสำเร็จ ระบบเพิ่มเมนูเข้าในรายการสั่งซื้อชั่วคราวอัตโนมัติ หากเข้าสู่ระบบไม่สำเร็จหรือผู้ใช้ยกเลิก ระบบยกเลิกเฉพาะเมนูที่เลือกไว้ก่อนเข้าสู่ระบบ
- **ASM-03:** โปรโมชั่นและเมนูแสดงบนหน้าเดียวกัน และเมนูที่มีโปรโมชั่นจะแสดงด้านบนสุด
- **ASM-04:** หากไม่มีโปรโมชั่นที่กำลังใช้งานอยู่ ระบบจะไม่แสดงส่วนโปรโมชั่น แต่ยังแสดงเมนูที่เปิดขายและเมนูที่หมดสต็อก โดยเมนูที่หมดสต็อกแสดงสถานะ “หมด” และปุ่ม “สั่งซื้อ” กดไม่ได้
- **ASM-05:** เมื่อโหลดข้อมูลเมนูหรือโปรโมชั่นไม่สำเร็จ ปุ่ม “ลองใหม่” จะโหลดข้อมูลเมนูและโปรโมชั่นใหม่
- **ASM-06:** การเลือกเมนูจากหน้า UC-01 ยังไม่ถือว่าเป็นการสร้าง Order
- **ASM-07:** ราคาที่ส่งต่อไปยัง UC-03 เป็นราคาหลังหักโปรโมชั่นตามที่ UC-01 คำนวณไว้ และ UC-03 จะไม่คำนวณส่วนลดซ้ำ
- **ASM-08:** การกลับไปหน้าเมนูเพื่อเลือกเครื่องดื่มเพิ่มเติมต้องเก็บรายการเดิมในรายการสั่งซื้อชั่วคราวไว้
- **ASM-09:** รายการที่เลือกก่อนหรือหลังเข้าสู่ระบบเป็นรายการสั่งซื้อชั่วคราว ไม่ใช่ Order ที่สมบูรณ์; Order ที่สมบูรณ์สร้างหลังชำระเงินสำเร็จตาม UC-03
- **ASM-10:** ภารกิจทดสอบ usability คือให้ผู้ใช้ค้นหาเครื่องดื่มชื่อ [ชื่อเมนูทดสอบ] จากหน้ารายการเมนู; ถือว่าสำเร็จเมื่อผู้ใช้ป้อนชื่อและพบรายการตรงกับชื่อที่กำหนดได้เองโดยไม่ขอความช่วยเหลือ
- **ASM-11:** ก่อนยืนยันคำสั่งซื้อให้ตรวจข้อมูลราคา โปรโมชั่น และสถานะสินค้าล่าสุด; หากข้อมูลเปลี่ยนต้องแจ้งผู้ใช้และให้ตรวจสอบ/ยืนยันอีกครั้ง หากสถานะสินค้าเป็น “หมด” ห้ามยืนยันรายการนั้น และต้องไม่คำนวณส่วนลดซ้ำ ทั้งนี้ผู้รับผิดชอบการตรวจ/คำนวณยังรอคำตอบ

### Open Questions

- **Q-05:** ในระดับการออกแบบระบบ จะใช้กลไกใดจัดเก็บและส่งต่อเมนูที่เลือกไว้ระหว่าง UC-01, UC-02 และ UC-03? ต้องถามทีมเจ้าของการออกแบบการเชื่อมต่อระหว่าง use case
- **Q-06:** โปรโมชั่นใช้ข้อมูลและสูตร/เงื่อนไขใดในการคำนวณราคาหลังหักส่วนลด? ต้องถามทีมเจ้าของข้อกำหนดการจัดการโปรโมชั่นใน UC-09
- **Q-07:** ส่วนใดเป็นผู้รับผิดชอบตรวจสอบราคา โปรโมชั่น และสถานะสินค้าล่าสุดก่อนยืนยัน และคำนวณราคาหลังเปลี่ยนแปลงโดยไม่คำนวณส่วนลดซ้ำ? ต้องถามทีมเจ้าของ UC-01/UC-03 และผู้กำหนดกติกาโปรโมชั่น
- **Q-08:** การวัด p95 2 วินาทีเริ่มและสิ้นสุดที่จุดใด และต้องใช้ข้อมูล/รูปแบบโหลดทดสอบใด? ต้องถามทีมผู้กำหนด/ผู้รับผิดชอบทดสอบประสิทธิภาพ
- **Q-09:** ต้องระบุรายละเอียดหน้าจอ (UI) หรือ mockup สำหรับหน้าเมนูและ flow ที่เชื่อม UC-02/UC-03 เพิ่มเติมหรือไม่? ต้องถามทีมเจ้าของข้อกำหนด

### Resolved Decisions

- **Q-03 (ปิดแล้ว):** หากระบบไม่มีรายการเครื่องดื่มเลย หน้าเมนูต้องแสดงข้อความ “ขณะนี้ไม่มีรายการเครื่องดื่ม” บันทึกผ่าน CR-MENU-001
- **Q-04 (ปิดแล้ว):** เปลี่ยนพฤติกรรมปุ่ม “สั่งซื้อ” จากการแสดงข้อความว่ายังไม่เปิดบริการ เป็นการเริ่มต้นขั้นตอนสั่งซื้อ โดยผู้ใช้ต้องเข้าสู่ระบบก่อนเพิ่มเครื่องดื่มเข้า Order บันทึกการตัดสินใจใน Draft v8
- **คำตอบ /clarify รอบนี้:** รายการก่อนยืนยันเป็นรายการสั่งซื้อชั่วคราว; Order ที่สมบูรณ์สร้างหลังชำระเงินสำเร็จตาม SPEC-ORDER-001; ใช้สถานะ “หมด” เป็นเงื่อนไขไม่อนุญาตให้ยืนยันรายการ; กำหนดภารกิจค้นหาใน AC-MENU-07 แล้ว
