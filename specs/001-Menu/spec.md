  # UC-01 — Feature: ดูเมนูและโปรโมชั่น (Menu & Promotion)

  Spec ID: SPEC-MENU-001 | Source: SRS v0.1 ข้อ 3.1 (FR-MENU) | Use case: UC-01  
  Owner: \<ทีม/คน> | Status: Draft v8 | Updated: 2569-10-26  
  Depends on: SPEC-ACCOUNT-001, SPEC-ORDER-001 | Reviewed by: -

  ## Goal

  นักศึกษา / ลูกค้า (ผู้ใช้ทั่วไปของระบบเมนูและโปรโมชั่นเดียวกัน) สามารถดูรายการเครื่องดื่ม ราคา รายละเอียด สถานะสินค้า และโปรโมชั่นของร้าน OWL CHA รวมถึงค้นหาเครื่องดื่มจากชื่อเมนู เพื่อใช้ข้อมูลประกอบการตัดสินใจก่อนสั่งซื้อ และสามารถเลือกเครื่องดื่มเพื่อเข้าสู่ขั้นตอนการสั่งซื้อได้ โดยต้องเข้าสู่ระบบก่อนเพิ่มเครื่องดื่มเข้า Order

  ## Scope

  ### In scope

  - ดูรายการเครื่องดื่มที่ร้านเปิดขายและรายการที่หมดสต็อก
  - ดูชื่อ ราคา รายละเอียด และสถานะของเครื่องดื่มแต่ละรายการ
  - ค้นหาเครื่องดื่มจากชื่อเมนู
  - ดูโปรโมชั่นที่กำลังใช้งานอยู่
  - แสดงราคาหลังหักโปรโมชั่นสำหรับเมนูที่มีโปรโมชั่น
  - เริ่มต้นขั้นตอนสั่งซื้อโดยเลือกเครื่องดื่มจากหน้าเมนู
  - นำผู้ใช้ที่ยังไม่ได้เข้าสู่ระบบไปยัง UC-02 เพื่อเข้าสู่ระบบหรือสมัครสมาชิกก่อนเพิ่มเครื่องดื่มเข้า Order
  - เก็บเมนูที่ผู้ใช้เลือกไว้ระหว่างเข้าสู่ระบบ และเพิ่มเมนูเข้า Order อัตโนมัติเมื่อเข้าสู่ระบบสำเร็จ
  - ยกเลิกเมนูที่เลือกไว้ก่อนเข้าสู่ระบบ หากเข้าสู่ระบบไม่สำเร็จหรือผู้ใช้ยกเลิกขั้นตอนเข้าสู่ระบบ
  - ส่งรายการเครื่องดื่มที่เลือกไปยัง UC-03 เพื่อดำเนินการสั่งซื้อ
  - โหลดข้อมูลเมนูและโปรโมชั่นใหม่เมื่อผู้ใช้กดปุ่ม “ลองใหม่”

  ### Out of scope

  - การกรองเครื่องดื่มตามประเภท (FR-04)
  - การสมัครสมาชิกและการตรวจสอบข้อมูลเข้าสู่ระบบ ซึ่งเป็นหน้าที่ของ UC-02
  - การกำหนดจำนวนและตัวเลือกของเครื่องดื่มใน Order
  - การแก้ไขจำนวนหรือลบรายการใน Order
  - การยืนยันคำสั่งซื้อและการสร้าง Order
  - การชำระเงินออนไลน์
  - การตรวจสอบสถานะ Order
  - การรับแจ้งเตือนเมื่อเครื่องดื่มพร้อมรับ
  - การดูและอัปเดต Order ของพนักงาน
  - การจัดการเมนู ราคา โปรโมชั่น และสถานะสินค้า
  - การดูรายงานยอดขายและสถิติ

  ## Constraints

  - ผู้ใช้ทั่วไปสามารถดูข้อมูลเมนูและโปรโมชั่นได้โดยไม่ต้องเข้าสู่ระบบ
  - ผู้ใช้ต้องเข้าสู่ระบบก่อนเพิ่มเครื่องดื่มเข้า Order
  - หากผู้ใช้ยังไม่ได้เข้าสู่ระบบ ระบบต้องนำผู้ใช้ไปยัง UC-02 ก่อนเพิ่มเครื่องดื่มเข้า Order
  - ระบบต้องเก็บเมนูที่เลือกไว้ระหว่างเข้าสู่ระบบ และเพิ่มเมนูเข้า Order อัตโนมัติเมื่อเข้าสู่ระบบสำเร็จ
  - หากเข้าสู่ระบบไม่สำเร็จหรือผู้ใช้ยกเลิกขั้นตอนเข้าสู่ระบบ ระบบต้องยกเลิกรายการที่เลือกไว้ก่อนเข้าสู่ระบบ โดยไม่กระทบ Order อื่นที่มีอยู่
  - การค้นหาเมนูต้องค้นหาจากชื่อเมนูแบบ partial match และไม่แยกตัวพิมพ์เล็ก/ใหญ่
  - เมนูที่หมดสต็อกต้องแสดงสถานะ “หมด” และไม่สามารถกดสั่งซื้อได้
  - ระบบต้องแสดงเฉพาะโปรโมชั่นที่กำลังใช้งานอยู่
  - เมนูที่มีโปรโมชั่นต้องแสดงอยู่ด้านบนสุดของรายการเมนู
  - ราคาที่ส่งต่อไปยัง UC-03 ต้องเป็นราคาหลังหักโปรโมชั่นตามที่ระบบคำนวณไว้ โดย UC-03 ไม่คำนวณส่วนลดซ้ำ
  - การเลือกเมนูจากหน้า UC-01 ยังไม่ถือว่าเป็นการสร้าง Order
  - การโหลดข้อมูลใหม่ต้องโหลดทั้งข้อมูลเมนูและโปรโมชั่น

  ## Requirements

  ### FR-01: แสดงรายการเครื่องดื่ม

  ระบบต้องแสดงรายการเครื่องดื่มที่เปิดให้แสดงบนหน้าร้าน รวมถึงเมนูที่หมดสต็อก หากระบบไม่มีรายการเครื่องดื่มเลย ระบบต้องแสดงข้อความ “ขณะนี้ไม่มีรายการเครื่องดื่ม”

  ### FR-02: แสดงรายละเอียดและเริ่มต้นการสั่งซื้อ

  ระบบต้องแสดงชื่อ ราคา รายละเอียด และสถานะของเครื่องดื่มแต่ละรายการ

  - เมนูที่เปิดขายและมีสต็อกต้องมีปุ่ม “สั่งซื้อ”
  - เมื่อผู้ใช้ที่เข้าสู่ระบบแล้วคลิกปุ่ม “สั่งซื้อ” ระบบต้องนำเมนูที่เลือกเข้าสู่ขั้นตอนการเพิ่มเครื่องดื่มเข้า Order ตาม UC-03 โดยยังไม่สร้าง Order ในขั้นตอนนี้
  - เมื่อผู้ใช้ที่ยังไม่ได้เข้าสู่ระบบคลิกปุ่ม “สั่งซื้อ” ระบบต้องเก็บเมนูที่เลือกไว้และนำผู้ใช้ไปยัง UC-02 เพื่อเข้าสู่ระบบหรือสมัครสมาชิกก่อนเพิ่มเครื่องดื่มเข้า Order
  - เมื่อเข้าสู่ระบบสำเร็จ ระบบต้องเพิ่มเมนูที่เลือกไว้เข้า Order โดยอัตโนมัติ และนำผู้ใช้ไปยังขั้นตอนการสั่งซื้อใน UC-03
  - หากเข้าสู่ระบบไม่สำเร็จหรือผู้ใช้ยกเลิกขั้นตอนเข้าสู่ระบบ ระบบต้องยกเลิกเมนูที่เลือกไว้ก่อนเข้าสู่ระบบ
  - เมนูที่หมดสต็อกต้องแสดงสถานะ “หมด” และปุ่ม “สั่งซื้อ” ต้องไม่สามารถใช้งานได้

  ### FR-03: ค้นหาเครื่องดื่ม

  ผู้ใช้สามารถค้นหาเครื่องดื่มจากชื่อเมนูได้แบบ partial match โดยไม่แยกตัวพิมพ์เล็ก/ใหญ่ เมื่อไม่พบรายการที่ตรงกับคำค้น ระบบต้องแสดงข้อความ “ไม่พบเมนู”

  ### FR-05: แสดงโปรโมชั่น

  ระบบต้องแสดงโปรโมชั่นที่กำลังใช้งานอยู่บนหน้าเมนูเดียวกัน และจัดเรียงเมนูที่มีโปรโมชั่นไว้ด้านบนสุด

  สำหรับเมนูที่มีโปรโมชั่น ระบบต้องคำนวณและแสดงราคาหลังหักโปรโมชั่น และส่งราคาดังกล่าวต่อไปยัง UC-03 โดย UC-03 ไม่คำนวณส่วนลดซ้ำ

  หากไม่มีโปรโมชั่นที่กำลังใช้งานอยู่ ระบบต้องไม่แสดงส่วนโปรโมชั่น แต่ยังคงแสดงรายการเครื่องดื่มทั้งเมนูที่เปิดขายและเมนูที่หมดสต็อก โดยเมนูที่หมดสต็อกต้องแสดงสถานะ “หมด” และปุ่ม “สั่งซื้อ” ต้องไม่สามารถใช้งานได้

  ### Alternative Flow Requirement

  - **FR-02 / UC-01 Alternative Flow 2a:** หากผู้ใช้ยังไม่ได้เข้าสู่ระบบและคลิกปุ่ม “สั่งซื้อ” ระบบต้องเก็บเมนูที่เลือกไว้และนำผู้ใช้ไปยัง UC-02
  - **FR-02 / UC-01 Alternative Flow 2b:** หากผู้ใช้เข้าสู่ระบบสำเร็จ ระบบต้องเพิ่มเมนูที่เลือกไว้เข้า Order อัตโนมัติและนำผู้ใช้ไปยัง UC-03
  - **FR-02 / UC-01 Alternative Flow 2c:** หากผู้ใช้ต้องการสั่งเครื่องดื่มเพิ่มเติม ระบบต้องให้ผู้ใช้กลับไปยังหน้าเมนูเพื่อเลือกเครื่องดื่มเพิ่มเติม โดยเก็บรายการเดิมใน Order ไว้

  ### Exception Flow Requirement

  - **UC-01 Exception Flow 2a:** หากระบบไม่สามารถโหลดข้อมูลเมนูหรือโปรโมชั่นได้ ระบบต้องแสดงข้อความแจ้งว่าไม่สามารถโหลดข้อมูลได้ และมีปุ่ม “ลองใหม่” เพื่อโหลดข้อมูลเมนูและโปรโมชั่นใหม่อีกครั้ง
  - **UC-01 Exception Flow 2b:** หากเข้าสู่ระบบไม่สำเร็จหรือผู้ใช้ยกเลิกขั้นตอนเข้าสู่ระบบ ระบบต้องยกเลิกเมนูที่เลือกไว้ก่อนเข้าสู่ระบบ และไม่เพิ่มเมนูดังกล่าวเข้า Order

  ## Quality Requirements

  - **NFR-22:** หน้าเมนูต้องตอบสนองภายใน 2 วินาที (p95) ภายใต้จำนวนผู้ใช้พร้อมกัน 100 concurrent users
  - **NFR-26:** ผู้ใช้ใหม่อย่างน้อย 8 ใน 10 คน ต้องสามารถค้นหาเมนูบนหน้าเมนูได้โดยไม่ต้องขอความช่วยเหลือ

  ## Acceptance Criteria

  ### AC-MENU-01 (FR-01)

  Given ร้านมีรายการเครื่องดื่มที่เปิดให้แสดงบนหน้าร้าน  
  When ผู้ใช้เปิดหน้ารายการเมนู  
  Then ระบบแสดงรายการเครื่องดื่มที่เปิดให้แสดงบนหน้าร้าน

  Given ระบบไม่มีรายการเครื่องดื่มเลย  
  When ผู้ใช้เปิดหน้ารายการเมนู  
  Then ระบบแสดงข้อความ “ขณะนี้ไม่มีรายการเครื่องดื่ม”

  ### AC-MENU-02 (FR-02)

  Given ผู้ใช้เข้าสู่ระบบแล้วและมีเมนูที่เปิดขาย  
  When ผู้ใช้คลิกปุ่ม “สั่งซื้อ” ของเมนูนั้น  
  Then ระบบนำเมนูที่เลือกเข้าสู่ขั้นตอนการสั่งซื้อใน UC-03 โดยยังไม่สร้าง Order

  Given ผู้ใช้ยังไม่ได้เข้าสู่ระบบและมีเมนูที่เปิดขาย  
  When ผู้ใช้คลิกปุ่ม “สั่งซื้อ”  
  Then ระบบเก็บเมนูที่เลือกไว้และนำผู้ใช้ไปยัง UC-02

  Given ผู้ใช้เข้าสู่ระบบสำเร็จหลังจากเลือกเมนูจาก UC-01  
  When ระบบดำเนินการหลังเข้าสู่ระบบสำเร็จ  
  Then ระบบเพิ่มเมนูที่เลือกไว้เข้า Order อัตโนมัติและนำผู้ใช้ไปยัง UC-03

  Given ผู้ใช้เข้าสู่ระบบไม่สำเร็จหรือยกเลิกขั้นตอนเข้าสู่ระบบ  
  When ระบบสิ้นสุดขั้นตอนเข้าสู่ระบบ  
  Then ระบบยกเลิกเมนูที่เลือกไว้ก่อนเข้าสู่ระบบและไม่เพิ่มเมนูดังกล่าวเข้า Order

  Given ระบบมีเมนูที่หมดสต็อก  
  When ผู้ใช้เปิดหน้ารายการเมนู  
  Then เมนูแสดงสถานะ “หมด” และปุ่ม “สั่งซื้อ” ไม่สามารถใช้งานได้

  ### AC-MENU-03 (FR-03)

  Given ระบบมีรายการเครื่องดื่มอยู่ในระบบ  
  When ผู้ใช้ค้นหาเครื่องดื่มจากชื่อเมนู  
  Then ระบบแสดงรายการเครื่องดื่มที่ตรงกับคำค้นแบบ partial match โดยไม่แยกตัวพิมพ์เล็ก/ใหญ่ และหากไม่พบรายการ ระบบแสดงข้อความ “ไม่พบเมนู”

  ### AC-MENU-04 (FR-05)

  Given ระบบมีโปรโมชั่นที่กำลังใช้งานอยู่  
  When ผู้ใช้เปิดหน้าเมนู  
  Then ระบบแสดงโปรโมชั่นที่กำลังใช้งานอยู่บนหน้าเมนูเดียวกัน แสดงราคาหลังหักโปรโมชั่น และจัดเรียงเมนูที่มีโปรโมชั่นไว้ด้านบนสุด

  Given ผู้ใช้เลือกเมนูที่มีโปรโมชั่นเพื่อเข้าสู่ UC-03  
  When ระบบส่งข้อมูลเมนูไปยัง UC-03  
  Then ระบบส่งราคาหลังหักโปรโมชั่นตามที่คำนวณไว้ โดย UC-03 ไม่คำนวณส่วนลดซ้ำ

  Given ไม่มีโปรโมชั่นที่กำลังใช้งานอยู่  
  When ผู้ใช้เปิดหน้าเมนู  
  Then ระบบไม่แสดงส่วนโปรโมชั่น แต่ยังแสดงเมนูที่เปิดขายและเมนูที่หมดสต็อก โดยเมนูที่หมดสต็อกแสดงสถานะ “หมด” และปุ่ม “สั่งซื้อ” ไม่สามารถใช้งานได้

  ### AC-MENU-05 (UC-01 Exception Flow 2a)

  Given ระบบไม่สามารถโหลดข้อมูลเมนูหรือโปรโมชั่นได้  
  When ผู้ใช้เปิดหน้ารายการเมนู  
  Then ระบบแสดงข้อความแจ้งว่าไม่สามารถโหลดข้อมูลได้ และมีปุ่ม “ลองใหม่”

  Given ผู้ใช้กดปุ่ม “ลองใหม่”  
  When ระบบเรียกโหลดข้อมูลอีกครั้ง  
  Then ระบบโหลดข้อมูลเมนูและโปรโมชั่นใหม่

  ### AC-MENU-06 (NFR-22)

  Given ระบบอยู่ภายใต้จำนวนผู้ใช้พร้อมกัน 100 concurrent users  
  When ผู้ใช้เปิดหน้าเมนู  
  Then p95 ของเวลาตอบสนองต้องไม่เกิน 2 วินาที

  ### AC-MENU-07 (NFR-26)

  Given ผู้ใช้ใหม่จำนวน 10 คน  
  When ผู้ใช้แต่ละคนทำภารกิจค้นหาเมนูบนหน้าเมนู  
  Then ผู้ใช้อย่างน้อย 8 คนต้องสามารถค้นหาเมนูบนหน้าเมนูได้โดยไม่ต้องขอความช่วยเหลือ

  ### AC-MENU-08 (UC-01 Alternative Flow 2a / 2b)

  Given ผู้ใช้ยังไม่ได้เข้าสู่ระบบและเลือกเมนูที่เปิดขาย  
  When ผู้ใช้คลิกปุ่ม “สั่งซื้อ” และเข้าสู่ระบบสำเร็จ  
  Then ระบบเพิ่มเมนูที่เลือกไว้เข้า Order อัตโนมัติและนำผู้ใช้ไปยัง UC-03

  ### AC-MENU-09 (UC-01 Exception Flow 2b)

  Given ผู้ใช้เลือกเมนูไว้ก่อนเข้าสู่ระบบ  
  When ผู้ใช้เข้าสู่ระบบไม่สำเร็จหรือยกเลิกขั้นตอนเข้าสู่ระบบ  
  Then ระบบยกเลิกเมนูที่เลือกไว้ก่อนเข้าสู่ระบบ และไม่กระทบ Order อื่นที่มีอยู่

  ## Assumptions and Open Questions

  ### Assumptions

  - **ASM-01:** การค้นหาเมนูทำแบบ partial match โดยไม่แยกตัวพิมพ์เล็ก/ใหญ่
  - **ASM-02:** ผู้ใช้ต้องเข้าสู่ระบบก่อนเพิ่มเครื่องดื่มเข้า Order หากยังไม่ได้เข้าสู่ระบบ ระบบจะเก็บเมนูที่เลือกไว้และนำผู้ใช้ไปยัง UC-02 เมื่อเข้าสู่ระบบสำเร็จ ระบบเพิ่มเมนูเข้า Order อัตโนมัติ หากเข้าสู่ระบบไม่สำเร็จหรือผู้ใช้ยกเลิก ระบบยกเลิกเมนูที่เลือกไว้ก่อนเข้าสู่ระบบ
  - **ASM-03:** โปรโมชั่นและเมนูแสดงบนหน้าเดียวกัน และเมนูที่มีโปรโมชั่นจะแสดงด้านบนสุด
  - **ASM-04:** หากไม่มีโปรโมชั่นที่กำลังใช้งานอยู่ ระบบจะไม่แสดงส่วนโปรโมชั่น แต่ยังแสดงเมนูที่เปิดขายและเมนูที่หมดสต็อก โดยเมนูที่หมดสต็อกแสดงสถานะ “หมด” และปุ่ม “สั่งซื้อ” กดไม่ได้
  - **ASM-05:** เมื่อโหลดข้อมูลเมนูหรือโปรโมชั่นไม่สำเร็จ ปุ่ม “ลองใหม่” จะโหลดข้อมูลเมนูและโปรโมชั่นใหม่
  - **ASM-06:** การเลือกเมนูจากหน้า UC-01 ยังไม่ถือว่าเป็นการสร้าง Order
  - **ASM-07:** ราคาที่ส่งต่อไปยัง UC-03 เป็นราคาหลังหักโปรโมชั่นตามที่ UC-01 คำนวณไว้ และ UC-03 จะไม่คำนวณส่วนลดซ้ำ
  - **ASM-08:** การกลับไปหน้าเมนูเพื่อเลือกเครื่องดื่มเพิ่มเติมต้องเก็บรายการเดิมใน Order ไว้

  ### Open Questions

  - วิธีจัดเก็บและส่งต่อเมนูที่เลือกไว้ระหว่าง UC-01 และ UC-02/UC-03 ในระดับการออกแบบระบบ
  - วิธีจัดการกรณีราคา โปรโมชั่น หรือสถานะสต็อกเปลี่ยนแปลงระหว่างที่ผู้ใช้เลือกเมนูกับการยืนยันคำสั่งซื้อ

  ### Resolved Decisions

  - **Q-03 (ปิดแล้ว):** หากระบบไม่มีรายการเครื่องดื่มเลย หน้าเมนูต้องแสดงข้อความ “ขณะนี้ไม่มีรายการเครื่องดื่ม” บันทึกผ่าน CR-MENU-001
  - **Q-04 (ปิดแล้ว):** เปลี่ยนพฤติกรรมปุ่ม “สั่งซื้อ” จากการแสดงข้อความว่ายังไม่เปิดบริการ เป็นการเริ่มต้นขั้นตอนสั่งซื้อ โดยผู้ใช้ต้องเข้าสู่ระบบก่อนเพิ่มเครื่องดื่มเข้า Order บันทึกการตัดสินใจใน Draft v8
